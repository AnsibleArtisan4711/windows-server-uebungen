## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| **PKI** | Public Key Infrastructure: Rollen, Regeln, Software und Zertifikate, die öffentliche Schlüssel an Identitäten binden. |
| **CA** | Certification Authority. Stellt Zertifikate aus und signiert sie mit ihrem privaten Schlüssel. |
| **RA** | Registration Authority. Prüft Antragsteller, bevor die CA ausstellt. In AD CS übernimmt die Richtlinie der CA diese Rolle. |
| **Zertifikat (X.509)** | Signierte Datenstruktur: Aussteller, Antragsteller, öffentlicher Schlüssel, Gültigkeit, Erweiterungen. |
| **Privater Schlüssel** | Geheimer Teil des Schlüsselpaars. Wer ihn hat, kann sich als Inhaber ausgeben. |
| **Root-CA** | Oberste CA einer Kette, sie signiert ihr eigenes Zertifikat (selbstsigniert). |
| **Subordinate CA** | Untergeordnete CA, ihr Zertifikat stammt von einer übergeordneten CA. |
| **SAN** | Subject Alternative Name. Erweiterung mit weiteren Namen (DNS, IP, UPN) des Antragstellers. |
| **CDP / AIA** | CRL Distribution Point / Authority Information Access: Adressen für Sperrliste und Ausstellerzertifikat. |
| **Standalone-CA** | Braucht kein Active Directory, Anträge werden meist manuell ausgestellt. |
| **Enterprise-CA** | Braucht Active Directory, nutzt Zertifikatvorlagen und kann automatisch ausstellen. |

### Teil 3: Fallstudie Zertifikatskette

*(Praxisaufgabe 1)*

Das fiktive Unternehmen „Corp“ plant eine zweistufige PKI: eine **Offline-Root-CA** (`Corp-Root-CA`) und eine **ausstellende Enterprise-CA** (`Corp-Issuing-CA`). Zeichne auf Papier oder Whiteboard:

- die Zertifikatskette (Root → Issuing → Endzertifikat für einen Webserver und für einen Benutzer),
- wer wem vertraut und woher die Clients das Root-Zertifikat bekommen,
- wo die Sperrlisten (CDP) und die Ausstellerzertifikate (AIA) abrufbar sind,
- was passiert, wenn der private Schlüssel der Root-CA kompromittiert wird.

## Hinweise

- Zeichne die Kette von oben nach unten. Jede Linie bedeutet „hat signiert“.
- Eine Offline-Root ist ausgeschaltet. Überlege, welche Informationen trotzdem immer abrufbar sein müssen (Sperrliste, Ausstellerzertifikat) und von wem sie bereitgestellt werden.
- Das Labor der folgenden Module setzt genau diese Zeichnung um. Heb sie auf.

## Kontrollfragen

1. Warum benötigt eine Enterprise-CA zwingend eine Active-Directory-Umgebung, während eine Standalone-CA auch in einer Arbeitsgruppe funktioniert?
2. Welche Informationen sind gemäß RFC 5280 zwingend in einem X.509-Zertifikat enthalten?
3. Welchen Zweck erfüllt die „Subject Alternative Name“ (SAN)-Erweiterung in modernen Zertifikaten?
4. Nennen Sie drei Unterschiede zwischen einer Standalone- und einer Enterprise-CA (Active-Directory-Integration, Zertifikatvorlagen, Genehmigung von Anträgen).
5. Welche Aufgaben haben CA, RA und der private Schlüssel, und was bedeutet die Kompromittierung des Schlüssels einer Root-CA?

## Musterlösung

<details>
<summary>Antworten (erst nach dem Versuch öffnen)</summary>

**Zielzustand:** `modul01-ergebnisse.md` mit Begriffen, Pflichtfeldern, Tabelle und einer Zeichnung.

```text
 Corp-Root-CA  (Standalone, offline, selbstsigniert)
      |  signiert
      v
 Corp-Issuing-CA  (Enterprise, online, Mitglied der Domäne)
      |  signiert
      +--> Zertifikat Webserver  (www.corp.internal)
      +--> Zertifikat Benutzer / Computer
 Clients erhalten das Root-Zertifikat über Active Directory (Modul 04).
 CDP/AIA: HTTP-Adresse auf dem Webserver der Issuing-CA (pki.corp.internal).
```

**Antworten**

1. Die Enterprise-CA liest Vorlagen, Gruppen und Konten aus dem Active Directory und veröffentlicht ihre Daten dort. Ohne Verzeichnis fehlen ihr diese Grundlagen. Die Standalone-CA nutzt nur die Angaben im Antrag.
2. Nach RFC 5280 sind das im Kern Version, Seriennummer, Signaturalgorithmus, Aussteller, Gültigkeit, Antragsteller, öffentlicher Schlüssel und die Signatur. Den genauen Wortlaut prüfst du im RFC (*nicht erneut gelesen*).
3. Er enthält die Namen (DNS, IP, UPN), für die das Zertifikat gilt. Moderne Browser prüfen den SAN und nicht mehr nur den Common Name.
4. Enterprise: AD-Integration, Vorlagen, Autoenrollment möglich. Standalone: keine AD-Pflicht, keine Vorlagen, Anträge werden oft manuell genehmigt.
5. CA signiert Zertifikate, RA prüft Antragsteller, der private Schlüssel beweist die Identität. Ist der Root-Schlüssel kompromittiert, sind alle darunter ausgestellten Zertifikate nicht mehr vertrauenswürdig, die PKI muss neu aufgebaut werden.

</details>
