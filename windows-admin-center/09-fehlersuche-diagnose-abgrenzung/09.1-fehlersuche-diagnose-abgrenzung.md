# 09.1 Fehlersuche, Diagnosewerkzeuge und Abgrenzung: drei Störungen und die Wahl des Werkzeugs

| **Geschätzte Zeit** | 3 bis 5 Stunden (Schätzung; Lehrplan: 6 UE zu 45 Minuten = 4,5 Stunden) |

| **Vorwissen** | Modul 02 und 03 |

> [!WARNING]
> **Stand der Prüfung: Entwurf, nicht im Labor ausgeführt.** Entwurf, nicht im Labor ausgeführt. Gegen Microsoft Learn gelesen (12.11.2026): Prüfung von Dienst und Port mit `Test-NetConnection -Port … -InformationLevel Detailed`, Dienst `WinRM`, `TrustedHosts`, Ereigniskanal *WindowsAdminCenter*. **Nicht bestätigt:** Browsermeldungen und Fehlertexte der Störungen. Notiere sie wörtlich. Hinweis: Die Reichweite der Werkzeuge für Active Directory, DHCP und DNS im Windows Admin Center ist nicht bestätigt (Lehrplan, Modul 1).

## Lernziele

Nach dieser Übung kannst du

- Dienst, Port, Ereignisprotokoll und Netzwerkverbindung des Gateways systematisch prüfen
- drei vorgegebene Störungen eingrenzen und beheben
- begründet entscheiden, wann Windows Admin Center, Server-Manager, PowerShell oder RSAT/MMC das passende Werkzeug ist

## Voraussetzungen

- Module 02 und 03 abgeschlossen. Kein Prio-2-Modul ist nötig.
- Prüfpunkt `vor-M9` auf beiden VMs vor Beginn.

## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| Eingrenzen | Eine Störung in Schritte zerlegen (Dienst, Port, Namen, Anmeldedaten) und jeweils nur eine Sache ändern. |
| Test-NetConnection | Prüft, ob ein TCP-Port erreichbar ist. |
| Ereigniskanal WindowsAdminCenter | Protokoll des Gateways und der Verwaltungsaktionen. |
| Ersatzzugang | Zugang, der unabhängig vom getesteten Weg funktioniert (hier die Hyper-V-Konsole). |

## Testumgebung

| Gerät | Rolle in Modul 09 |
|---|---|
| Host | Prüfpunkte, Konsolenzugang |
| WAC01 | Gateway und Browser |
| ZIEL01 | Zielserver |

## Aufgabe

### Teil 1: Werkzeugkasten im Gutzustand

*(Lerneinheit 9.1, Praxisaufgabe 1)*

Erstelle zuerst auf dem Host den Prüfpunkt:

```powershell
foreach ($vm in 'WAC01','ZIEL01') { Checkpoint-VM -Name $vm -SnapshotName 'vor-M9' }
```

Führe die Prüfungen einmal im Gutzustand aus. Auf `WAC01`:

```powershell
Get-Service WindowsAdminCenter
Test-NetConnection -ComputerName wac01.wac.internal -Port 443 -InformationLevel Detailed
Get-Item WSMan:\localhost\Client\TrustedHosts
Get-WinEvent -LogName 'WindowsAdminCenter' -MaxEvents 5
```

Auf `ZIEL01`:

```powershell
Get-Service WinRM
```

### Teil 2: Störung 1 (Gateway-Dienst)

*(Lerneinheit 9.2, Praxisaufgabe 2)*

Auf `WAC01`:

```powershell
Stop-Service -Name WindowsAdminCenter
```

Rufe die Oberfläche auf und notiere die Browsermeldung. Grenze die Ursache mit den Schritten aus Teil 1 ein und behebe:

```powershell
Start-Service -Name WindowsAdminCenter
```

### Teil 3: Störung 2 (WinRM auf dem Ziel)

*(Praxisaufgabe 3)*

Der Prüfpunkt `vor-M9` existiert, Ersatzzugang ist die Hyper-V-Konsole. Auf `ZIEL01`:

```powershell
Stop-Service -Name WinRM -Force
```

Öffne die Verbindung zu `ziel01.wac.internal` und notiere die Meldung. Grenze die Ursache ein:

```powershell
Test-NetConnection ziel01.wac.internal -Port 5985
```

Beheben auf `ZIEL01` (Konsole):

```powershell
Start-Service -Name WinRM
```

### Teil 4: Störung 3 (TrustedHosts)

*(Praxisaufgabe 4)*

Auf `WAC01`: Notiere den Eintrag, leere ihn, öffne die Verbindung und notiere die Meldung.

```powershell
$alt = (Get-Item WSMan:\localhost\Client\TrustedHosts).Value
Clear-Item WSMan:\localhost\Client\TrustedHosts -Force
```

Stelle ihn wieder her und prüfe erneut:

```powershell
Set-Item WSMan:\localhost\Client\TrustedHosts -Value $alt -Force
Get-Item WSMan:\localhost\Client\TrustedHosts
```

### Teil 5: Dokumentation

*(Praxisaufgabe 5)*

Schreibe für jede Störung in drei Zeilen Symptom, Ursache, Prüfschritt und Behebung auf.

### Teil 6: Entscheidungshilfe (Fallstudie)

*(Lerneinheit 9.3, Praxisaufgabe 6)*

Entscheide für „Alpenwerk“ (zehn Server, ein Team) mit je einer Begründung, welche Aufgaben du im Windows Admin Center, im Server-Manager, in PowerShell oder mit RSAT/MMC erledigst (zum Beispiel eine Rolle installieren, ein Skript auf zehn Servern ausführen, einen Benutzer in AD anlegen, die Leistung beobachten). Führe auf, was nach deinen Quellen nicht klar ist.

### Teil 7: Rückbau

*(Praxisaufgabe 7)*

Prüfe, dass `WindowsAdminCenter` und `WinRM` laufen und `TrustedHosts` den Eintrag trägt. Sonst setze beide VMs gemeinsam auf `vor-M9` zurück.

## Hinweise

- Ändere nur eine Sache auf einmal.
- Beende `WinRM` auf dem Ziel erst, wenn Prüfpunkt und Konsolenzugang bereitstehen.
- Starte beendete Dienste wieder, bevor du weitermachst.

## Kontrollfragen

1. Welche drei Störungen hast du bearbeitet, und woran hast du jeweils die Ursache erkannt?
2. Welche Prüfung unterscheidet „Gateway nicht erreichbar“ von „Zielserver nicht erreichbar“?
3. Warum ist ein Prüfpunkt vor dem Beenden von `WinRM` sinnvoll, und welchen Ersatzzugang hast du?
4. Wann ist PowerShell dem Windows Admin Center vorzuziehen?

## Musterlösung

<details>
<summary>Antworten und Zielzustand (erst nach dem Versuch öffnen)</summary>

**Zielzustand**

- Drei Störungen dokumentiert und behoben, Dienste laufen, `TrustedHosts` wiederhergestellt, Entscheidungstabelle geschrieben.

**Antworten**

1. Gateway-Dienst gestoppt (Seite nicht erreichbar, Dienst und Port 443 geprüft), `WinRM` gestoppt (Verbindung zum Ziel schlägt fehl, Port 5985 geprüft), `TrustedHosts` leer (Verbindung wird abgelehnt, Eintrag geprüft).
2. `Test-NetConnection` gegen Port 443 des Gateways und gegen Port 5985 des Ziels: das erste prüft den Weg Browser → Gateway, das zweite Gateway → Ziel.
3. Beim Stoppen von `WinRM` kann das Gateway nicht mehr verwalten; ohne Prüfpunkt und Konsole müsstest du den Zustand mühsam retten. Ersatzzugang ist die Hyper-V-Konsole.
4. Bei Wiederholung, Skripten, vielen Servern und nachvollziehbarer Automatisierung. Die Begründung zählt.

</details>

## Erweiterungen

- Baue eine vierte Störung (zum Beispiel Firewallregel für 5985 aus) und löse sie mit denselben Schritten (danach zurücksetzen).
- Prüfe, wie das Ereignisprotokoll die Störungen widerspiegelt.
