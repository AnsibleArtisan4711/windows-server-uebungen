Gegen Microsoft Learn gelesen (12.11.2026): Gateway-Rollen, RBAC mit drei lokalen Gruppen, Einschränkungen der Leserrolle, Ereigniskanal *WindowsAdminCenter* mit Ereignis-ID 4000 und Quelle `SMEGateway`. **Nicht bestätigt:** der Menüname für den Zugriff auf das Gateway, die genaue Abfrage von `Get-WinEvent -LogName` für diesen Kanal, das Verhalten der Leserrolle in der Praxis und die Dauer der RBAC-Anwendung (Quelle: bis etwa zehn Minuten). Eine Anweisung zum Entfernen von RBAC ist nicht bestätigt; der Rückbau geschieht über den Prüfpunkt.

## Lernziele

Nach dieser Übung kannst du

- die Rollen für den Zugriff auf das Gateway und ihre Grenzen in einer Arbeitsgruppe beschreiben
- RBAC auf einem Zielserver einrichten und die drei lokalen Gruppen nutzen
- die Wirkung der Rolle *Readers* prüfen und die Protokollierung auswerten

## Voraussetzungen

- Modul 03 abgeschlossen.
- Prüfpunkt `vor-M6` auf beiden VMs vor Beginn.

## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| Gateway users / administrators | Rollen für den Zugriff auf das Gateway; lokale Administratoren des Gateways sind immer Gateway-Administratoren. |
| RBAC | Rollenbasierte Zugriffssteuerung auf dem Zielserver (über einen JEA-Endpunkt). |
| Windows Admin Center Readers | Lokale Gruppe mit lesendem Zugriff. |
| Ereignis 4000, Quelle `SMEGateway` | Eintrag für eine Verwaltungsaktion im Kanal *WindowsAdminCenter* des Zielservers. |

## Testumgebung

| Gerät | Rolle in Modul 06 |
|---|---|
| WAC01 | Gateway und Browser |
| ZIEL01 | Zielserver mit RBAC |

## Aufgabe

### Teil 1: Gateway-Zugriff lesen (nicht ändern)

*(Lerneinheit 6.1, Praxisaufgabe 1)*

Öffne die Einstellungen des Gateways zum Zugriff (Menüname nicht bestätigt) und notiere, wer Gateway-Benutzer und -Administrator ist. **Ändere nichts**, weil eine falsche Änderung den Zugang sperren kann; Ersatzzugang wäre die Hyper-V-Konsole von `WAC01`. Notiere, was in einer Arbeitsgruppe nicht möglich ist (laut Microsoft Learn keine gruppenbasierte Steuerung in Arbeitsgruppen).

### Teil 2: Konto anlegen

*(Praxisaufgabe 2)*

Auf dem Host erstellst du zuerst den Prüfpunkt:

```powershell
foreach ($vm in 'WAC01','ZIEL01') { Checkpoint-VM -Name $vm -SnapshotName 'vor-M6' }
```

Auf `ZIEL01`:

```powershell
$pw = Read-Host 'Kennwort für leser01' -AsSecureString
New-LocalUser -Name 'leser01' -Password $pw -PasswordNeverExpires
```

Der Benutzer ist **kein** Administrator.

### Teil 3: RBAC einschalten

*(Lerneinheit 6.2, Praxisaufgabe 3)*

Öffne die Einstellungen der Verbindung `ziel01.wac.internal` und wende *Role-based access control* an (*Settings → Role-based access control → Apply*, laut Microsoft Learn; dauert bis etwa zehn Minuten und startet WinRM neu). Danach auf `ZIEL01`:

```powershell
Get-LocalGroup -Name 'Windows Admin Center*'
```

Du erwartest die Gruppen *Windows Admin Center Administrators*, *… Hyper-V Administrators* und *… Readers*.

### Teil 4: Leserrolle prüfen

*(Praxisaufgabe 4)*

```powershell
Add-LocalGroupMember -Group 'Windows Admin Center Readers' -Member 'leser01'
```

Verbinde dich mit „Manage as“ als `leser01` (Name im Format `ziel01\leser01`). Laut Microsoft Learn sind in den eingeschränkten Rollen PowerShell, Remote Desktop und Storage Replica nicht verfügbar, im Werkzeug *Files* gibt es keinen Upload und Download. Prüfe, was du tatsächlich vorfindest, und notiere Abweichungen.

### Teil 5: Protokoll auswerten

*(Lerneinheit 6.3, Praxisaufgabe 5)*

Führe als `Administrator` eine Aktion aus (zum Beispiel Dienst `Spooler` neu starten). Auf `ZIEL01`:

```powershell
Get-WinEvent -LogName 'WindowsAdminCenter' -MaxEvents 10 | Format-List TimeCreated,Id,ProviderName,Message
```

Laut Microsoft Learn sind Ereignis-ID 4000 und die Quelle `SMEGateway` für Verwaltungsaktionen vorgesehen. Notiere aus der Meldung die Felder `UserOnGateway` und `UserOnTarget`.

### Teil 6: Rückbau

*(Praxisaufgabe 6)*

Setze beide VMs gemeinsam auf `vor-M6` zurück (im Hyper-V-Manager oder mit `Restore-VMCheckpoint`).

## Hinweise

- Ändere den Zugriff auf das Gateway im Labor nie ohne Ersatzzugang.
- RBAC startet WinRM auf dem Ziel neu; plane die Wartezeit ein.
- Kennwörter nur interaktiv eingeben.

## Kontrollfragen

1. Warum bedeutet Zugriff auf das Gateway nicht automatisch Zugriff auf die Zielserver?
2. Welche drei lokalen Gruppen entstehen durch RBAC, und welche Einschränkungen hat die Leserrolle?
3. Warum gibt es laut Quelle keine eigenen Rollen, und was bedeutet das für die Planung?
4. Welche Informationen enthält ein Protokolleintrag der Verwaltungsaktionen, und wie hilft er bei einer Untersuchung?

## Musterlösung

<details>
<summary>Antworten und Zielzustand (erst nach dem Versuch öffnen)</summary>

**Zielzustand**

- RBAC angewendet, drei Gruppen vorhanden, `leser01` als Leser geprüft, Protokolleintrag zur Beispielaktion gefunden, am Ende beide VMs auf `vor-M6` zurückgesetzt.

**Antworten**

1. Das Gateway verlangt für das Ziel eigene Administrator-Anmeldedaten oder „Manage as“. Der Zugriff auf das Gateway ist nur die erste Stufe.
2. *Windows Admin Center Administrators*, *… Hyper-V Administrators*, *… Readers*. Die Leserrolle darf lesen; PowerShell, Remote Desktop und Storage Replica sind laut Microsoft Learn nicht verfügbar, *Files* ohne Upload und Download.
3. Laut Quelle sind keine benutzerdefinierten Rollen vorgesehen. Plane deshalb mit den drei Rollen und dem Prinzip der geringsten Rechte.
4. Skript oder CIM-Aufruf, Werkzeug, Gateway, Benutzer am Gateway und am Ziel, Hinweis auf Delegierung, LAPS und Dateiname. Sie zeigen, wer wann was getan hat.

</details>
