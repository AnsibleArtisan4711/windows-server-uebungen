## Lernziele

Nach dieser Übung kannst du

- einen privaten Switch, statische Adressen und Namen über die Datei `hosts` für zwei Server einrichten
- einen Arbeitsgruppen-Zielserver für die Verwaltung per WinRM vorbereiten
- das Windows Admin Center im Gateway-Modus installieren und Dienst, Port und Anmeldung prüfen

## Voraussetzungen

- Modul 01 abgeschlossen.
- Das Installationsprogramm des Windows Admin Center und die Windows-Server-2025-Medien liegen auf dem Host (vor dem Labor aus dem Internet geladen, Quelle: Microsoft Evaluation Center).
- Beide VMs `WAC01` und `ZIEL01` sind installiert (Windows Server 2025 Evaluation, Desktopdarstellung), das Kennwort des lokalen `Administrator` ist vergeben.

## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| Arbeitsgruppe | Rechner ohne Domäne; Anmeldung mit lokalen Konten. |
| TrustedHosts | Liste von Zielen, die ein WinRM-Client ohne gegenseitige Authentifizierung ansprechen darf (nötig außerhalb einer Domäne). |
| Dienst `WindowsAdminCenter` | Dienstname des modernisierten Gateways; ältere Builds hießen `ServerManagementGateway`. |
| Gateway-Modus | Installation auf einem Server, auf den Administratoren im Browser zugreifen. |

## Testumgebung

| Gerät | Rolle in Modul 02 |
|---|---|
| Host | Switch, Prüfpunkte, Installationsdatei per VHDX oder ISO |
| WAC01 | 192.168.80.10, Gateway und Browser (Laborvereinfachung) |
| ZIEL01 | 192.168.80.20, Verwaltungsziel |

## Aufgabe

### Teil 1: Netzwerk

*(Lerneinheit 2.1, Praxisaufgabe 1)*

Auf dem Host:

```powershell
New-VMSwitch -Name 'vSwitch-WAC-Privat' -SwitchType Private
foreach ($vm in 'WAC01','ZIEL01') { Connect-VMNetworkAdapter -VMName $vm -SwitchName 'vSwitch-WAC-Privat' }
```

Auf `WAC01` (Adaptername mit `Get-NetAdapter` prüfen):

```powershell
New-NetIPAddress -InterfaceAlias 'Ethernet' -IPAddress 192.168.80.10 -PrefixLength 24
```

Auf `ZIEL01` entsprechend mit `192.168.80.20`. Kein Gateway, kein DNS. Prüfe von `WAC01`:

```powershell
Test-NetConnection 192.168.80.20
```

Beachte: Die Windows-Firewall blockiert Ping im öffentlichen Profil. Ein Fehlschlag heißt deshalb nicht zwingend, dass das Netz falsch ist. Teste dann mit einem offenen Port nach Teil 3.

### Teil 2: Namen über die Datei hosts

*(Lerneinheit 2.1, Praxisaufgabe 2)*

Auf beiden VMs in einer Konsole mit Administratorrechten:

```powershell
Add-Content -Path "$env:SystemRoot\System32\drivers\etc\hosts" -Value "192.168.80.10 wac01.wac.internal wac01"
Add-Content -Path "$env:SystemRoot\System32\drivers\etc\hosts" -Value "192.168.80.20 ziel01.wac.internal ziel01"
Test-NetConnection ziel01.wac.internal
```

Ob `Resolve-DnsName` die Datei `hosts` auswertet, ist nicht bestätigt; die Prüfung mit `Test-NetConnection` genügt.

### Teil 3: Zielserver vorbereiten

*(Lerneinheit 2.2, Praxisaufgabe 3)*

Auf `ZIEL01`:

```powershell
Get-Service WinRM
Enable-PSRemoting -Force
Get-NetFirewallRule -Name WINRM-HTTP-In-TCP-PUBLIC | Format-List Name,Enabled,RemoteAddress
```

Beide Server liegen im selben Subnetz; die Regel braucht deshalb keine Änderung der erlaubten Adressen. Gelingt `Enable-PSRemoting` wegen des Netzwerkprofils nicht, lies die Fehlermeldung und notiere sie (Lösung nicht bestätigt; die Ursache gehört in dein Protokoll).

### Teil 4: TrustedHosts und Prüfpunkt

*(Lerneinheit 2.2, Praxisaufgabe 4)*

Auf `WAC01`:

```powershell
Set-Item WSMan:\localhost\Client\TrustedHosts -Value 'ziel01.wac.internal,192.168.80.20' -Force
Get-Item WSMan:\localhost\Client\TrustedHosts
Test-NetConnection ziel01.wac.internal -Port 5985
$cred = Get-Credential -UserName 'ziel01\Administrator' -Message 'Lokaler Administrator von ZIEL01'
Test-WSMan -ComputerName ziel01.wac.internal -Credential $cred -Authentication Negotiate
```

Die Kombination aus `-Credential` und `-Authentication` ist nicht bestätigt; funktioniert sie nicht, genügt der Test auf Port 5985. Danach auf dem Host:

```powershell
foreach ($vm in 'WAC01','ZIEL01') { Checkpoint-VM -Name $vm -SnapshotName 'M2-Basis' }
```

### Teil 5: Installation

*(Lerneinheit 2.3, Praxisaufgabe 5)*

Kopiere das Installationsprogramm auf `WAC01` (virtuelle Festplatte oder ISO vom Host). Starte es und wähle die Installationsart für den **Gateway-Server** (bei Bedarf *Custom setup*). Nimm Port **443** und das vom Installer erzeugte selbstsignierte Zertifikat (laut Microsoft Learn nur für Tests, Laufzeit 60 Tage). Schalte die automatische Aktualisierung und die Übermittlung von Diagnosedaten aus, soweit der Assistent diese Optionen anbietet (Wortlaut nicht bestätigt). Danach:

```powershell
Get-Service WindowsAdminCenter
Get-NetTCPConnection -LocalPort 443 -State Listen
```

### Teil 6: Erster Start und Prüfpunkt

*(Lerneinheit 2.4, Praxisaufgabe 6)*

Öffne in Edge auf `WAC01` `https://wac01.wac.internal`. Die Zertifikatswarnung ist erwartet (selbstsigniertes Zertifikat); sie wird in Modul 05 behoben. Melde dich mit dem lokalen `Administrator` an (Ablauf nicht bestätigt) und notiere die Version (Fundstelle in der Oberfläche nicht bestätigt). Dann auf dem Host:

```powershell
foreach ($vm in 'WAC01','ZIEL01') { Checkpoint-VM -Name $vm -SnapshotName 'M2-WAC' }
```

## Hinweise

- Der Switch ist privat und hat kein Gateway: nichts verlässt das Labor.
- Trage in `TrustedHosts` nur die beiden Ziele ein, nie `*`.
- Kennwörter nur interaktiv eingeben und nicht notieren.
- Den Browser auf dem Gateway selbst zu nutzen ist eine Laborvereinfachung; in der Praxis greift man von einem Arbeitsplatz zu.

## Kontrollfragen

1. Warum ist der virtuelle Switch privat, und warum hat er kein Gateway?
2. Wozu dient `TrustedHosts`, und warum ist ein Eintrag wie `*` im Labor eine schlechte Gewohnheit?
3. Warum läuft der Browser im Labor auf `WAC01`, und was wäre in der Praxis besser?
4. Warum erscheint die Zertifikatswarnung, und warum ist sie in Modul 02 zulässig, aber nicht auf Dauer?

## Musterlösung

<details>
<summary>Antworten und Zielzustand (erst nach dem Versuch öffnen)</summary>

**Zielzustand**

- Beide VMs im Netz `192.168.80.0/24`, Namen über `hosts`, WinRM auf `ZIEL01` erreichbar (Port 5985), `TrustedHosts` mit den zwei Zielen, Gateway installiert, Dienst läuft, Port 443 lauscht, Anmeldung im Browser möglich. Prüfpunkte `M2-Basis` und `M2-WAC`.

**Antworten**

1. Damit keine Pakete in andere Netze gelangen. Ohne Gateway gibt es keinen Weg hinaus.
2. Außerhalb einer Domäne kann der Client den Zielserver nicht per Kerberos prüfen. `TrustedHosts` erlaubt die Verbindung trotzdem. Ein `*` erlaubt sie zu jedem Ziel und senkt den Schutz.
3. Es gibt keinen Arbeitsplatz im privaten Netz. In der Praxis greift man von einem Arbeitsplatz zu und nicht vom Server aus.
4. Das Zertifikat ist selbstsigniert und dem Browser unbekannt. Es ist für Tests gedacht und läuft laut Microsoft Learn nach 60 Tagen ab.

</details>

## Erweiterungen

- Installiere das Gateway auf einem anderen Port (zum Beispiel 8443) parallel und prüfe, was sich ändert (neu anlegen, danach wieder entfernen; Verhalten nicht bestätigt).
- Lies das Ereignisprotokoll *WindowsAdminCenter* nach der Installation.
