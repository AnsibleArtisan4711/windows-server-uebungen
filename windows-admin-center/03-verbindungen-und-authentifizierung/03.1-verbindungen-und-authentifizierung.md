## Lernziele

Nach dieser Übung kannst du

- Server als Verbindung hinzufügen, mit alternativen Anmeldedaten verwalten und taggen
- Verbindungslisten importieren und gemeinsame Verbindungen einrichten
- Authentifizierungsarten und Clusterverbindungen erklären; die Einmalanmeldung in einer Domäne beschreiben (Theorie)

## Aufgabe

### Teil 1: Server hinzufügen

*(Lerneinheit 3.1, Praxisaufgabe 1)*

Wähle auf der Startseite *All connections → Add*, den Typ **Servers** und gib `ziel01.wac.internal` ein. Gib bei Aufforderung die Anmeldedaten des lokalen `Administrator` von `ZIEL01` an. Öffne die Verbindung und notiere die Spalte *Managing As*.

### Teil 2: Anmeldedaten wechseln

*(Praxisaufgabe 2)*

Wähle bei der Verbindung *Manage as* und gib die Anmeldedaten erneut an. Beschreibe, wie lange sie gelten: Werden sie auf alle Verbindungen angewendet, gelten sie laut Quelle für die Browsersitzung; nach dem Neuladen musst du sie erneut eingeben.

### Teil 3: Tags und Importliste

*(Lerneinheit 3.2, Praxisaufgabe 3)*

Vergib der Verbindung das Tag `labor`. Entferne sie dann aus der Liste. Lege auf `WAC01` eine Textdatei an, die nur eine Zeile enthält:

```powershell
Set-Content -Path "$env:USERPROFILE\ziele.txt" -Value 'ziel01.wac.internal'
```

Füge die Verbindung über *Import a list* wieder hinzu und setze die Anmeldedaten erneut mit *Manage as*. Laut Microsoft Learn sind `.txt` und `.csv` möglich; eine durch PowerShell exportierte `.csv` mit zusätzlichen Spalten eignet sich nicht.

### Teil 4: Gemeinsame Verbindungen

*(Praxisaufgabe 4)*

Öffne als Gateway-Administrator (Mitglied der lokalen Administratorgruppe auf `WAC01`) die Einstellungen des Gateways, Reiter *Shared Connections*, und lege `ziel01.wac.internal` an. Prüfe auf *All connections*, dass die Gruppen *Personal* und *Shared* erscheinen.

### Teil 5: Theorie Einmalanmeldung

*(Lerneinheit 3.3, Praxisaufgabe 5)*

Beschreibe schriftlich, warum die Einmalanmeldung bei einem Gateway auf Windows Server eine Kerberos-Delegierung braucht. Gib den Befehl aus der Quelle sinngemäß wieder:

```powershell
# NICHT ausführen: im Labor gibt es keine Domäne.
Set-ADComputer -Identity (Get-ADComputer ziel01) -PrincipalsAllowedToDelegateToAccount (Get-ADComputer wac01)
```

Erkläre, warum in der Arbeitsgruppe stattdessen „Manage as“ nötig ist.

### Teil 6: Theorie Cluster

*(Praxisaufgabe 6)*

Beschreibe in drei Sätzen, wie ein Failover-Cluster als eigene Verbindung hinzugefügt wird (Typ *Server clusters*, laut Microsoft Learn) und warum das im Kurs nicht geübt wird.

## Hinweise

- Das Gateway merkt sich die Verbindungsliste pro Benutzer.
- Gemeinsame Verbindungen enthalten keine Anmeldedaten.
- Der Befehl in Teil 5 ist nur Text zum Erklären.

## Kontrollfragen

1. Was steht in der Spalte *Managing As*, und wozu dient sie?
2. Warum funktioniert die Einmalanmeldung im Labor nicht?
3. Welche Wirkung hat die gemeinsame Verbindungsliste für andere Benutzer des Gateways?
4. Wie unterscheidet sich die Verbindung zu einem Cluster von der Verbindung zu den einzelnen Knoten?

## Musterlösung

<details>
<summary>Antworten und Zielzustand (erst nach dem Versuch öffnen)</summary>

**Zielzustand**

- `ziel01.wac.internal` als Verbindung mit Tag `labor`, auch als gemeinsame Verbindung. Schriftliche Antworten zu Einmalanmeldung und Cluster.

**Antworten**

1. Sie zeigt das Konto, unter dem das Gateway den Zielserver verwaltet. Sie macht sichtbar, wer wo handelt.
2. Die Einmalanmeldung braucht Kerberos und eine Delegierung vom Gateway zum Ziel. Eine Arbeitsgruppe hat keine Domäne und keine Kerberos-Delegierung.
3. Alle Benutzer des Gateways sehen die Verbindungen in der Gruppe *Shared*, können sie aber nicht ändern.
4. Ein Cluster-Eintrag zeigt Clusterressourcen, Rollen, Netzwerke und Speicher; die einzelnen Knoten lassen sich zusätzlich als Server hinzufügen (laut Microsoft Learn).

</details>
