> [!WARNING]
> **Stand der Prüfung: Entwurf, nicht im Labor ausgeführt.** Gegen Microsoft Learn geprüft (12.11.2026): `Get-WsusUpdate` kennt `-Classification` mit den Werten `All`, `Critical`, `Security`, `WSUS`, `-Approval` (`Approved`, `Unapproved`, `AnyExceptDeclined`, `Declined`) und `-Status` (u. a. `Needed`, `Failed`, `FailedOrNeeded`, `Any`) sowie `-UpdateId`; `Approve-WsusUpdate` setzt `-Action` und `-TargetGroupName`. **Definitionsupdates lassen sich mit `-Classification` nicht gezielt filtern**, dafür filterst du nach `All` und danach selbst. Die Eigenschaftsnamen am Ergebnisobjekt (`Update.Title` usw.), `GetContentDownloadProgress()`, der Warnhinweis zur Schaltfläche „Regel ausführen“ (laut *Deploy Windows client updates using WSUS*) und alle Menünamen sind *nicht bestätigt* bzw. Lehrplanangabe.

## Lernziele

Nach dieser Übung kannst du

- die Update-Status „Erforderlich“, „Installiert“ und „Nicht zutreffend“ unterscheiden,
- Updates für eine Gruppe genehmigen und ablehnen,
- eine automatische Genehmigungsregel anlegen und die Gefahr der Schaltfläche „Regel ausführen“ erklären,
- ein genehmigtes Update über WSUS auf dem Client installieren.

## Voraussetzungen

- Module 03 und 05 abgeschlossen: Produkte „Windows 11“ und „Microsoft Defender Antivirus“, Klassifizierungen u. a. „Definitionsupdates“ synchronisiert, `CLIENT01` in „Test-Clients“.
- Für Aufgabe 4 eine **Internetphase** für `WSUS01`.
- **Vorab Prüfpunkte** anlegen (Host):

```powershell
Checkpoint-VM -Name WSUS01, CLIENT01 -SnapshotName 'vor-M6'
```

## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| **Erforderlich (Needed)** | Der Client braucht das Update und hat es nicht. |
| **Installiert** | Das Update ist installiert. |
| **Nicht zutreffend** | Das Update betrifft den Client nicht (anderes Produkt, schon ersetzt, andere Voraussetzung). |
| **Genehmigung** | Freigabe eines Updates für eine Gruppe (zur Installation, zum Entfernen u. a.). |
| **Ablehnen (Decline)** | Das Update wird für niemanden angeboten und taucht in Standardansichten nicht auf. |
| **Automatische Genehmigungsregel** | Genehmigt bestimmte neue Updates (nach Klassifizierung und Produkt) für eine Gruppe automatisch. |
| **Ersetzt (superseded)** | Ein neueres Update ersetzt ein älteres. |

## Testumgebung

| Gerät | Rolle in Modul 06 |
|---|---|
| WSUS01 | WSUS-Server (in der Internetphase mit `EXTERN`) |
| CLIENT01 | Mitglied von `Test-Clients`, installiert das Update |

## Aufgabe

### Teil 1: Manuelle Genehmigung

*(Lerneinheiten 6.1 und 6.2, Praxisaufgabe 1)*

Menüweg: *WSUS-Konsole → Updates → Alle Updates*, Filter *Genehmigung: Alle*, *Status: Erforderlich*, dann *Aktualisieren*. Suche ein kleines Update, am besten ein neues **Definitionsupdate** (Klassifizierung „Definitionsupdates“, Produkt „Microsoft Defender Antivirus“). Rechtsklick → *Genehmigen* → Gruppe `Test-Clients` → *Zur Installation freigegeben*. Updates mit Lizenzbedingungen (EULA) musst du zuerst akzeptieren.

Per PowerShell. Zuerst auflisten und die gewünschte ID merken (*Eigenschaftsnamen nicht bestätigt*):

```powershell
Get-WsusUpdate -Classification All -Approval Unapproved -Status Needed |
  Where-Object { $_.Update.UpdateClassificationTitle -like '*Definition*' } |
  Select-Object -First 5 -ExpandProperty Update |
  Select-Object Id, Title, UpdateClassificationTitle
```

Dann genehmigen (die ID aus der Liste einsetzen):

```powershell
Get-WsusUpdate -UpdateId '<UpdateId>' |
  Approve-WsusUpdate -Action Install -TargetGroupName 'Test-Clients'
```

Notiere den Titel des Updates. Dieses eine Update installierst du in Teil 4.

### Teil 2: Ablehnen

*(Praxisaufgabe 2)*

Menüweg: Wähle ein Update, das `CLIENT01` nicht braucht → Rechtsklick → *Ablehnen*. Prüfe mit dem Filter *Genehmigung: Abgelehnt*, dass es dort steht. Per PowerShell (*Cmdlet-Name aus der Modulliste, Parameter nicht geprüft*):

```powershell
Get-WsusUpdate -UpdateId '<UpdateId>' | Deny-WsusUpdate
Get-WsusUpdate -Classification All -Approval Declined | Select-Object -First 5 -ExpandProperty Update | Select-Object Title
```

Notiere den Titel für Modul 08, dort verschwindet das Update bei der Bereinigung möglicherweise.

### Teil 3: Automatische Genehmigungsregel

*(Lerneinheit 6.3, Praxisaufgabe 3)*

Menüweg: *Optionen → Automatische Genehmigungen → Neue Regel*, Klassifizierung *Sicherheitsupdates*, Gruppe `Test-Clients`, Name `Sicherheitsupdates → Test-Clients`.

> **Klicke nicht auf „Regel ausführen“.** Das genehmigt **alle** passenden Updates, auch ältere, was sehr große Downloads auslösen kann (Quelle: *Deploy Windows client updates using WSUS*).

Entferne anschließend das Häkchen der Regel, damit sie **deaktiviert** ist. Sonst würde in Teil 4 mehr als das eine Update genehmigt.

Schreibe in zwei bis drei Sätzen, wann die aktivierte Regel Updates genehmigen würde. Laut Microsoft Learn sind das neu synchronisierte Updates, nicht rückwirkend.

### Teil 4: Installation auf dem Client (Internetphase)

*(Praxisaufgabe 4)*

WSUS lädt die Dateien erst nach der Genehmigung. Dafür braucht `WSUS01` jetzt Internet.

**1. Internet zuschalten (Host)**

```powershell
Connect-VMNetworkAdapter -VMName WSUS01 -Name 'EXTERN' -SwitchName 'Default Switch'
```

(Hast du den Adapter in Modul 03 komplett entfernt statt getrennt, legst du ihn mit `Add-VMNetworkAdapter` wie dort wieder an, Namen und Registrierungsoption wie in Modul 03 setzen.)

**2. Download abwarten (auf WSUS01)**

In der WSUS-Konsole zeigt die Übersicht bzw. die Update-Eigenschaften den Dateistatus. Per API (*nicht bestätigt*):

```powershell
$p = (Get-WsusServer).GetContentDownloadProgress()
'{0} von {1} Bytes' -f $p.DownloadedBytes, $p.TotalBytesToDownload
```

Warte, bis beide Zahlen gleich sind.

**3. Internet trennen (Host)**

```powershell
Disconnect-VMNetworkAdapter -VMName WSUS01 -Name 'EXTERN'
```

**4. Auf CLIENT01 scannen und installieren**

```powershell
(New-Object -ComObject Microsoft.Update.AutoUpdate).DetectNow()
```

Dann *Einstellungen → Windows Update*. Option 3 benachrichtigt vor der Installation, gegebenenfalls löst du die Installation manuell aus. Das genehmigte Update erscheint in der Liste.

**5. Erfolg im WSUS prüfen**

Die Rückmeldung des Clients kann dauern. In der WSUS-Konsole zeigt das Update dann „Installiert“ für `CLIENT01`:

```powershell
Get-WsusUpdate -UpdateId '<UpdateId>' | Select-Object -ExpandProperty Update | Select-Object Title
```

(Der Status je Computer steht in der Konsole unter dem Update → Statusbericht. Per PowerShell ist die Abfrage umständlicher und *nicht bestätigt*.)

## Hinweise

- Das Zurücksetzen mit dem Prüfpunkt `vor-M6` ist erlaubt, wenn du Updates genehmigt hast, die Gigabytes laden.
- „Erforderlich“ ist nicht dasselbe wie „genehmigt“. Ein Update kann gebraucht, aber nicht genehmigt sein.
- Die Option „Dateien lokal speichern“ ist Standard, nur die Dateien der genehmigten Updates werden geladen.

## Kontrollfragen

1. Was bedeutet der Status „Nicht zutreffend“ bei einem Update?
2. Warum sollten Updates für Server-Infrastrukturen in der Regel nicht durch automatische Genehmigungsregeln freigegeben werden?
3. Was geschieht, wenn ein Update für eine Gruppe auf „Ablehnen“ gesetzt wird?
4. Warum sollte die Schaltfläche „Regel ausführen“ bei einer Regel für Sicherheitsupdates nicht unüberlegt verwendet werden?

## Musterlösung

<details>
<summary>Antworten und Zielzustand (erst nach dem Versuch öffnen)</summary>

**Zielzustand**

- Genau ein Definitionsupdate ist für `Test-Clients` genehmigt, heruntergeladen und auf `CLIENT01` installiert.
- Ein anderes Update steht unter „Abgelehnt“.
- Die automatische Regel besteht und ist deaktiviert.
- `EXTERN` ist wieder getrennt.

**Antworten**

1. Das Update betrifft den Computer nicht (anderes Produkt, schon durch ein neueres ersetzt oder Voraussetzung nicht erfüllt). Es muss nicht installiert werden.
2. Ungeprüfte Updates könnten Dienste stören. Server brauchen Test und Wartungsfenster, siehe Testgruppe (Modul 05).
3. Es wird nicht mehr angeboten. Genehmigungen für die Updates fallen für alle Gruppen weg, weil „Ablehnen“ serverweit gilt (*Wirkung nicht bestätigt, in der Konsole prüfen*).
4. Die Schaltfläche genehmigt rückwirkend alle passenden Updates, nicht nur neue. Das kann sehr große Downloads und eine ungeplante Verteilung auslösen.

</details>
