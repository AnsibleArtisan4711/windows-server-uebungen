# 04.1 Clients per Gruppenrichtlinie an WSUS binden und die Verbindung prüfen

| | |
|---|---|
| **Modul** | 04 Client-Anbindung mittels Gruppenrichtlinien (GPO) |
| **Stufe** | Grundlagen |
| **Geschätzte Zeit** | 6 bis 8 Stunden (Schätzung; Lehrplan: 10 UE zu 45 Minuten = 7,5 Stunden) |
| **Werkzeuge** | Gruppenrichtlinienverwaltung, Windows PowerShell, WSUS-Konsole, Ereignisanzeige |
| **Vorwissen** | Modul 03 (laufender WSUS-Dienst), GPO anlegen und mit einer OU verknüpfen |

> [!WARNING]
> **Stand der Prüfung: Entwurf, nicht im Labor ausgeführt.** Die Registrywerte der Richtlinie (`WUServer`, `WUStatusServer`, `UseWUServer`, `AUOptions`) und der Bezug der GPO-Einstellungen zu den Windows-Update-Richtlinien stammen aus den Microsoft-Learn-Seiten *Step 2: Configure WSUS* und *Deploy Windows client updates using WSUS* (Lehrplanquellen, am 12.11.2026 für diese Reihe gegen die Seiten abgeglichen, soweit sie erreichbar waren). Die Cmdlets `New-GPO`, `New-GPLink` und `Set-GPRegistryValue` kommen aus dem Modul `GroupPolicy`, ihre Parameter sind **nicht einzeln geprüft**. **Nicht bestätigt** sind: die deutschen Bezeichnungen der Einstellungen und Menüs, die Firewall-Regel für Port 8530 und die Wirkung von `usoclient`.

## Lernziele

Nach dieser Übung kannst du

- ein GPO erstellen, das Clients an den internen WSUS-Server bindet, und es an die richtige OU hängen,
- erklären, wozu Update-Dienst und Statistikserver beide gesetzt werden,
- die Wirkung auf dem Client prüfen (Erreichbarkeit, Registry, WSUS-Konsole, Ereignisanzeige),
- einen Scan auslösen, ohne auf nicht dokumentierte Werkzeuge zu bauen.

## Voraussetzungen

- Modul 03 abgeschlossen, WSUS läuft, Prüfpunkt `M3-WSUS` vorhanden.
- `CLIENT01` ist Mitglied der Domäne und steht in der OU `Clients`.
- Angemeldet als `WSUSLAB\Administrator`.

## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| **Updatedienst-URL** | Adresse, von der der Client Updates ermittelt: `http://wsus01.wsuslab.internal:8530`. |
| **Statistikserver** | Adresse, an die der Client seine Statusberichte sendet. Meist dieselbe URL. |
| **Port 8530 / 8531** | WSUS ohne bzw. mit SSL. |
| **Richtlinienpfad in der Registry** | `HKLM\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate`, darunter `AU`. |
| **AUOptions 3** | „Automatisch herunterladen und vor Installation benachrichtigen“. |
| **Scan** | Der Client fragt den Server nach passenden Updates. |

## Testumgebung

| Gerät | Rolle in Modul 04 |
|---|---|
| WSUS01 | Domänencontroller, WSUS-Server, GPO-Verwaltung |
| CLIENT01 | Domänenmitglied in `OU=Clients`, WSUS-Client |

Die GPO wird an die OU `Clients` gehängt, **nicht** an die Domäne. Sonst würde der Server `WSUS01` als Domänencontroller selbst zum Client seines eigenen WSUS.

## Aufgabe

### Teil 1: GPO anlegen und verknüpfen

*(Lerneinheit 4.1, Praxisaufgabe 1)*

Menüweg (auf WSUS01): *Server-Manager → Tools → Gruppenrichtlinienverwaltung → Domäne → Gruppenrichtlinienobjekte → Rechtsklick → Neu*, Name `WSUS-Clients`. Dann *OU Clients → Rechtsklick → Vorhandenes Gruppenrichtlinienobjekt verknüpfen*. PowerShell:

```powershell
New-GPO -Name 'WSUS-Clients'
New-GPLink -Name 'WSUS-Clients' -Target 'OU=Clients,DC=wsuslab,DC=internal'
```

### Teil 2: GPO konfigurieren

*(Lerneinheit 4.2, Praxisaufgabe 2)*

Menüweg: Rechtsklick auf `WSUS-Clients` → *Bearbeiten* → *Computerkonfiguration → Richtlinien → Administrative Vorlagen → Windows-Komponenten → Windows Update*. Bei Windows 10/11 liegen die Einstellungen in Unterknoten. Die Einstellung für den Updatedienst steht unter „Von Windows Server Update Service angebotene Updates verwalten“, „Automatische Updates konfigurieren“ unter „Endbenutzererfahrung verwalten“. Die deutschen Bezeichnungen sind *nicht bestätigt*.

- **Internen Pfad für den Microsoft Updatedienst angeben:** *Aktiviert*. **Beide** Felder auf `http://wsus01.wsuslab.internal:8530`: „Intranetupdatedienst zum Ermitteln von Updates festlegen“ und „Intranetstatistikserver festlegen“. Die URL muss mit `http://` oder `https://` beginnen.
- **Automatische Updates konfigurieren:** *Aktiviert*, Option **3** („Autom. Herunterladen und vor Installation benachrichtigen“).

Dieselben Werte als Registryeinstellung in der GPO (gleichwertig zur Oberfläche, *Cmdlet-Parameter nicht bestätigt*):

```powershell
$gpo = 'WSUS-Clients'
$wu  = 'HKLM\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate'
Set-GPRegistryValue -Name $gpo -Key $wu -ValueName 'WUServer'       -Type String -Value 'http://wsus01.wsuslab.internal:8530'
Set-GPRegistryValue -Name $gpo -Key $wu -ValueName 'WUStatusServer' -Type String -Value 'http://wsus01.wsuslab.internal:8530'
Set-GPRegistryValue -Name $gpo -Key "$wu\AU" -ValueName 'UseWUServer' -Type DWord -Value 1
Set-GPRegistryValue -Name $gpo -Key "$wu\AU" -ValueName 'NoAutoUpdate' -Type DWord -Value 0
Set-GPRegistryValue -Name $gpo -Key "$wu\AU" -ValueName 'AUOptions'   -Type DWord -Value 3
```

Verwende entweder die Oberfläche **oder** diese Befehle, nicht beides gemischt, sonst ist unklar, woher ein Wert kommt.

### Teil 3: Wirkung auf dem Client prüfen

*(Lerneinheit 4.3, Praxisaufgabe 3)*

**1. Erreichbarkeit (auf CLIENT01)**

```powershell
Test-NetConnection wsus01.wsuslab.internal -Port 8530
```

Erwartet (*sinngemäß*): `TcpTestSucceeded : True`. Schlägt es fehl, prüfe die Windows-Firewall auf `WSUS01`. Ob die WSUS-Installation die Regel selbst anlegt, ist *nicht bestätigt*:

```powershell
Get-NetFirewallRule -Direction Inbound | Where-Object DisplayName -like '*WSUS*'
```

Nur wenn keine passende Regel besteht, legst du im Labor selbst eine an:

```powershell
New-NetFirewallRule -DisplayName 'WSUS 8530 (Labor)' -Direction Inbound -Protocol TCP -LocalPort 8530 -Action Allow
```

**2. Richtlinie anwenden und Registry lesen (auf CLIENT01)**

```powershell
gpupdate /force
reg query HKLM\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate /v WUServer
reg query HKLM\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate /v WUStatusServer
```

Erwartet: beide Werte zeigen `http://wsus01.wsuslab.internal:8530`. In *Einstellungen → Windows Update* steht meist ein Hinweis, dass einige Einstellungen von der Organisation verwaltet werden (*sinngemäß*).

**3. Scan auslösen**

Am sichersten: *Einstellungen → Windows Update → Nach Updates suchen*. Für die Kommandozeile kennt der Windows-Update-Agent die COM-Schnittstelle `AutomaticUpdates`:

```powershell
(New-Object -ComObject Microsoft.Update.AutoUpdate).DetectNow()
```

`usoclient StartScan` ist nicht offiziell dokumentiert und seine Wirkung unter Windows 11 ist *nicht bestätigt*; verwende es nicht als Lösung. Auch `wuauclt /detectnow` gilt als veraltet.

**4. Ergebnis in der WSUS-Konsole**

*WSUS-Konsole → Computer → Alle Computer → Nicht zugewiesene Computer*. `CLIENT01` erscheint dort nach einigen Minuten. Erscheint er nicht, lies auf dem Client:

```powershell
Get-WinEvent -LogName 'Microsoft-Windows-WindowsUpdateClient/Operational' -MaxEvents 20 |
  Select-Object TimeCreated, Id, Message | Format-List
```

(Ereignisanzeige: *Anwendungs- und Dienstprotokolle → Microsoft → Windows → WindowsUpdateClient → Betriebsbereit*.)

## Hinweise

- Ein leerer Eintrag bei „Nicht zugewiesene Computer“ heißt oft nur, dass der Statusbericht noch aussteht. Warte einige Minuten und löse den Scan erneut aus.
- Steht `WUServer` nicht in der Registry, hat die GPO den Client nicht erreicht: prüfe die Verknüpfung an der OU, die Position von `CLIENT01` (Modul 02) und `gpresult /r`.
- Ändere in dieser Übung keinen Port. Fehler provozierst du erst in Modul 10.

## Kontrollfragen

1. Über welchen Standard-Port kommuniziert WSUS ohne SSL?
2. Warum muss in der GPO sowohl der Update-Dienst als auch der Statistikserver angegeben werden?
3. Wie lösen Sie unter Windows 11 eine sofortige Update-Suche aus, und was ist beim Werkzeug `usoclient` zu beachten?

## Musterlösung

<details>
<summary>Antworten und Zielzustand (erst nach dem Versuch öffnen)</summary>

**Zielzustand**

- GPO `WSUS-Clients`, verknüpft mit `OU=Clients`, nicht mit der Domäne.
- `WUServer` und `WUStatusServer` = `http://wsus01.wsuslab.internal:8530`, `UseWUServer` = 1, `AUOptions` = 3.
- `CLIENT01` erscheint in der WSUS-Konsole unter „Nicht zugewiesene Computer“.

**Antworten**

1. TCP **8530** (mit SSL 8531).
2. Der Updatedienst sagt, *woher* der Client Updates ermittelt, der Statistikserver, *wohin* er Statusberichte sendet. Fehlt der zweite, kann der Server den Stand des Clients nicht erfahren, und Berichte (Modul 07) bleiben leer.
3. Über *Einstellungen → Windows Update → Nach Updates suchen* oder per COM-Objekt (`DetectNow()`). `usoclient` ist nicht offiziell dokumentiert, seine Wirkung unter Windows 11 ist nicht bestätigt, daher nicht als Standardweg verwenden.

</details>

## Erweiterungen

- Stelle mit `gpresult /h C:\gpresult.html` einen Bericht auf `CLIENT01` aus und finde die Einstellung darin wieder.
- Lege eine Testgruppenrichtlinie ohne Verknüpfung an und prüfe, dass sich nichts ändert. So siehst du, wie wichtig die Verknüpfung ist.
