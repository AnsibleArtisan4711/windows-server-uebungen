## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| **Patch-Management** | Planmäßiges Beschaffen, Prüfen, Testen, Verteilen und Kontrollieren von Updates. |
| **WSUS** | Windows Server Update Services. Eine Windows-Server-Rolle, die Updates von Microsoft Update holt und intern an Clients verteilt. |
| **Metadaten** | Beschreibung eines Updates (Titel, Klassifizierung, Produkt, Ersetzungen). WSUS holt sie bei der Synchronisierung. |
| **Update-Dateien (Content)** | Die eigentlichen Installationsdateien. WSUS lädt sie standardmäßig erst nach der Genehmigung (Modul 03, 06). |
| **Upstream-/Downstream-Server** | Ein Upstream-Server liefert Updates an Downstream-Server weiter. |
| **WID** | Windows Internal Database. Eingebaute Datenbank, die WSUS standardmäßig nutzt. |
| **deprecated** | Sinngemäß: nicht mehr aktiv weiterentwickelt, aber (noch) unterstützt. Die genaue Aussage von Microsoft liest du in Aufgabe 3 nach. |

### Teil 1: Fallstudie Patch-Management

*(Lerneinheit 1.1, Praxisaufgabe 1)*

Das fiktive Unternehmen „Contoso Austria“ hat 150 Windows-11-Clients und 20 Windows-Server. Alle Clients holen ihre Updates heute einzeln direkt aus dem Internet. Die Geschäftsführung fragt, wozu ein zentrales Patch-Management gut sein soll.

Schreibe ein Konzept von **einer Seite**, das mindestens diese Punkte enthält:

1. Wozu dient Patch-Management (Sicherheitslücken schließen, Stabilität, Nachvollziehbarkeit)?
2. Welche Risiken entstehen, wenn jeder Client selbst und ungeprüft aus dem Internet aktualisiert (Fehlerhafte Updates treffen alle gleichzeitig, kein Überblick über den Stand, Bandbreite, keine Testphase)?
3. Was bedeutet „kontrolliert“? Nenne die Schritte Beschaffen, Testen, Freigeben, Kontrollieren.
4. Welche Rolle spielt der Baustein OPS.1.1.3 des BSI-IT-Grundschutz-Kompendiums? Gib nur wieder, was du in der Quelle selbst gelesen hast. Hast du ihn nicht gelesen, schreibe das dazu.

### Teil 2: Architekturskizze

*(Lerneinheit 1.2, Praxisaufgabe 2)*

## Musterlösung

<details>
<summary>Erwartete Kernaussagen (erst nach dem Versuch öffnen)</summary>

**Teil 1 (Stichpunkte, keine Mustertexte)**

- Ziel: bekannte Sicherheitslücken zeitnah schließen, ohne den Betrieb durch fehlerhafte Updates zu gefährden.
- Risiko bei Direktbezug: fehlerhafte Updates erreichen alle Geräte gleichzeitig, keine Testgruppe, kein zentraler Überblick, jeder Client lädt dieselben Dateien einzeln (Bandbreite), keine Nachweise für Audits.
- Kontrollierter Ablauf: Beschaffen (Synchronisierung), Testen (Testgruppe), Freigeben (Genehmigung), Kontrollieren (Berichte). Das sind die Module 03 bis 07 dieser Reihe.
- Zum BSI-Baustein: nur Aussagen aus dem gelesenen Text. Erwartet wird die Idee, dass Patches geplant, getestet und dokumentiert eingespielt werden. Der Wortlaut ist nicht Teil dieser Lösung (*nicht bestätigt*).

**Teil 2 (Datenflüsse)**

```text
 Microsoft Update (Internet)
        |  (1) Metadaten  (immer)
        |  (2) Update-Dateien  (erst nach Genehmigung)
        v
 +-------------------------------------+
 | WSUS-Server                         |
 |   IIS (Web-Dienste, Port 8530)      |
 |   Datenbank (WID oder SQL Server)   |
 |   Inhaltsordner (Update-Dateien)    |
 +-------------------------------------+
        ^  |                       |
 (3)    |  | Updates + Metadaten   | optional: Downstream-WSUS
 Status-|  v                       v  (holt von diesem Server)
 bericht|
 +---------------------+
 | Clients (per GPO)   |
 +---------------------+
```

- Metadaten: Microsoft Update → WSUS (bei der Synchronisierung).
- Update-Dateien: Microsoft Update → WSUS (nach Genehmigung), danach WSUS → Client.
- Statusberichte: Client → WSUS (Scan-/Installationsergebnis).

**Teil 3 (Kernaussagen laut Seite, Stand 12.11.2026, mit der Seite zu prüfen)**

- „No longer actively developed“: Das Produkt wird nicht mehr aktiv weiterentwickelt, bleibt aber unterstützt.
- WSUS: nicht mehr aktiv entwickelt, weiter unterstützt, erhält Sicherheits- und Qualitätsupdates.
- Windows Internal Database: als deprecated geführt; die Seite nennt eine Ersatzkomponente. Welche, steht dort, ich gebe sie hier bewusst nicht aus dem Gedächtnis wieder.
- Folge für Neuplanungen: WSUS ist für Neuinstallationen kein Produkt mit Zukunftsfunktionen. Wer neu plant, prüft Alternativen (Modul 12) und plant für WSUS eine Datenbank, die nicht die WID ist, oder einen Ausstieg.

**Kontrollfragen**

1. Geplant, getestet und nachvollziehbar patchen verringert das Zeitfenster bekannter Lücken und das Risiko durch fehlerhafte Updates.
2. WSUS-Server (Rolle), IIS, Datenbank (WID oder SQL Server), Inhaltsordner, Verbindung zu Microsoft Update, Clients mit Richtlinie, DNS und Netzwerk.
3. Keine neuen Funktionen mehr, weiterhin Sicherheits- und Qualitätsupdates. Neuplanung sollte Alternativen und das Ende der WID berücksichtigen.

</details>
