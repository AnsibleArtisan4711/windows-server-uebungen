## Lernziele

Nach dieser Übung kannst du

- WSUS, Windows Update for Business (WUfB) und Cloud-Lösungen vergleichen,
- das Konzept der Deployment Rings erklären,
- einen Migrationsweg von WSUS zu WUfB und Intune skizzieren,
- beurteilen, wofür der Azure Update Manager gedacht ist, und eine Behauptung an der Quelle prüfen.

## Voraussetzungen

- Modul 01 abgeschlossen, besonders die Notizen zum Lebenszyklus von WSUS.
- Zugang zu den Microsoft-Seiten zu Windows Update for Business, Intune-Update-Richtlinien und Azure Update Manager (Suche über Microsoft Learn).

## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| **WUfB** | Windows Update for Business: Update-Verwaltung über Richtlinien, ohne eigenen Update-Server. |
| **Deployment Ring** | Stufe der Einführung (zum Beispiel Pilot, Breite, Rest), die Updates zeitversetzt erhält. |
| **Intune** | Cloud-Dienst zur Geräteverwaltung. |
| **Delivery Optimization (Übermittlungsoptimierung)** | Verfahren, bei dem Clients Update-Teile voneinander beziehen und so Bandbreite sparen. |
| **Azure Update Manager** | Azure-Dienst zur Update-Verwaltung für Server (Azure und, über Azure Arc, andere Standorte). |
| **Azure Arc** | Dienst, der Server außerhalb von Azure in Azure verwaltbar macht. |

## Aufgabe

### Teil 1: Konzept Cloud-Migration

*(Lerneinheiten 12.1 und 12.2, Praxisaufgabe 1)*

Erstelle eine Migrationsskizze für „Contoso Austria“ (siehe Modul 01): Die Windows-11-Clients sollen künftig über WUfB und Intune statt über WSUS mit Updates versorgt werden. Die Skizze (eine bis zwei Seiten) enthält:

1. **Ausgangslage** (kurz aus Modul 01 übernehmen),
2. **Zielbild**: wie Richtlinien, Deployment Rings und Berichte künftig organisiert sind,
3. **Schritte der Migration**, geordnet nach Reihenfolge und Risiko (zum Beispiel erst Pilotgruppe, dann Breite),
4. **Beantworte die Frage**, wie die Netzwerkauslastung ohne lokalen WSUS reduziert werden kann (Stichwort: Delivery Optimization),
5. **Offene Risiken** (Netzabhängigkeit, Kosten, Berichtsfähigkeit) und was du vor einer Entscheidung klären musst.

Gib bei jeder Sachaussage die Quelle an.

### Teil 2: Recherche zum Azure Update Manager

*(Lerneinheit 12.3, Praxisaufgabe 2)*

Ermittle anhand der Microsoft-Dokumentation (Quelle angeben), **welche Server-Betriebssysteme** durch den Azure Update Manager (über Azure Arc) verwaltet werden können. Gib an, welche Seite du verwendet hast und wann du sie gelesen hast. Nenne nur, was dort steht.

### Teil 3: Beurteilung

Bewerte schriftlich die Aussage: „Der Azure Update Manager ist der Nachfolger von WSUS für Server.“ Ist sie in den von dir verwendeten Quellen **belegt**? Wenn nicht, was ist belegt?

## Hinweise

- „Nicht belegt“ ist eine gültige und gute Antwort, wenn die Quelle eine Behauptung nicht trägt.
- Trenne Fakten (mit Quelle) von deiner Einschätzung. Markiere die Einschätzung ausdrücklich als solche.
- Die Lehrplan-Quellenseite (*Features removed or no longer developed in Windows Server*) nennt WSUS als nicht mehr aktiv weiterentwickelt. Ob dort ein Nachfolger genannt wird, prüfst du selbst.

## Kontrollfragen

1. Wie löst WUfB das Problem der Zielgruppenadressierung im Vergleich zu WSUS? (Stichwort: Deployment Rings)
2. Welche Technologie in Windows 10/11 hilft dabei, Bandbreite beim Download direkt aus dem Internet (WUfB) zu sparen?
3. Für welche Einsatzszenarien eignet sich der Azure Update Manager (Server, hybrid über Azure Arc) und für welche Intune bzw. Windows Update for Business (Clients)? Beurteilen Sie anhand der Quellen, ob die Aussage „Der Azure Update Manager ist der Nachfolger von WSUS für Server“ belegt ist.

## Musterlösung

<details>
<summary>Erwartete Kernaussagen (erst nach dem Versuch öffnen)</summary>

**Zu Teil 1 (Gerüst, keine Produktdetails)**

- Statt Computergruppen auf einem Server (Modul 05) definierst du Richtlinien und Deployment Rings in der Verwaltung. Gruppenzuordnung erfolgt über Geräte- oder Benutzergruppen der Cloud-Verwaltung.
- Migrationsreihenfolge: Bestand aufnehmen, Zielbild festlegen, Pilotring, schrittweise Verbreiterung, WSUS-Richtlinie (GPO) für migrierte Geräte ablösen, WSUS zuletzt stilllegen.
- Bandbreite: Delivery Optimization, kein lokaler WSUS als Zwischenspeicher mehr.

**Zu Teil 2**

- Du nennst die Betriebssysteme, die auf der von dir gelesenen Seite stehen, mit Seite und Datum. Eine Aufzählung aus dem Gedächtnis zählt nicht.

**Zu Teil 3**

- Die Aussage „Nachfolger“ wird nur gewertet, wenn eine Microsoft-Seite sie so formuliert. In der Lehrplanquelle zum Lebenszyklus (Stand 12.11.2026) wird WSUS als nicht mehr aktiv weiterentwickelt geführt; dass ein bestimmter Dienst als Nachfolger benannt wird, ist in dieser Reihe **nicht belegt**. Ein Azure-Dienst für Server und Cloud-Verwaltung für Clients kann **Alternativen** zu WSUS bieten, ohne dass das ein „Nachfolger“ ist.

**Kontrollfragen**

1. Updates werden nicht in Computergruppen auf einem Server genehmigt, sondern in Ringen eingeführt, die Richtlinien zugeordnet sind. Zeit und Gerätegruppe sind in der Richtlinie festgelegt.
2. Delivery Optimization (Übermittlungsoptimierung).
3. Azure Update Manager: Server, auch hybrid über Azure Arc. Intune/WUfB: Clients. Die Nachfolger-Aussage ist nur belegt, wenn deine Quelle sie enthält.

</details>
