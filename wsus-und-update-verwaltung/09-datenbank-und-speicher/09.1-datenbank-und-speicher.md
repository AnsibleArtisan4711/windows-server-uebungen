## Lernziele

Nach dieser Übung kannst du

- WID und dedizierten SQL Server für WSUS unterscheiden,
- die Verbindung zur WID herstellen und `SUSDB` sichern,
- das Reindex-Skript ausführen und das Protokoll auswerten,
- den Inhaltsordner verschieben und den Rückbau durchführen.

## Voraussetzungen

- Module 03 und 08 abgeschlossen, WSUS läuft, `CLIENT01` meldet.
- Für Aufgabe 1 eine **Internetphase** auf `WSUS01` (Download von `sqlcmd` und des Skripts).
- Pfade im Labor: `C:\Skripte`, `C:\Backup`, `C:\WSUS`, `C:\WSUS_New`.

## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| **SUSDB** | Name der WSUS-Datenbank. |
| **WID** | Windows Internal Database. Eingebaute Datenbank, nur lokal erreichbar. |
| **Named Pipe** | Lokale Verbindungsart zur WID, kein Netzwerkport. |
| **`sqlcmd`** | Kommandozeilenwerkzeug für T-SQL. |
| **Reindex** | Neuaufbau oder Reorganisation fragmentierter Indizes. |
| **`WsusUtil.exe`** | Kommandozeilenwerkzeug von WSUS (`postinstall`, `movecontent`, `configuressl`, `reset` u. a.). |

## Aufgabe

### Teil 1: Vorbereitung (Internetphase)

*(Lerneinheit 9.1, Praxisaufgabe 1)*

Verbinde `WSUS01` kurz mit dem Internet (wie in Modul 03) und beschaffe:

- die `sqlcmd`-Werkzeuge: *Microsoft Command Line Utilities for SQL Server* samt passendem ODBC-Treiber (Paketnamen und Versionen *nicht bestätigt*, prüfe die aktuelle Microsoft-Downloadseite),
- das T-SQL-Skript von der Seite *Reindex the WSUS database* (Link unter *Quellen*).

```powershell
New-Item -Path 'C:\Skripte' -ItemType Directory -Force
New-Item -Path 'C:\Backup'  -ItemType Directory -Force
```

Speichere das Skript als `C:\Skripte\SUSDBMaint.sql`. Installiere `sqlcmd`. Trenne `EXTERN` wieder.

### Teil 2: Verbindung herstellen und sichern

*(Lerneinheit 9.2, Praxisaufgabe 2)*

**1. Prüfen, dass SUSDB auf der WID läuft**

```powershell
Get-ItemProperty 'HKLM:\Software\Microsoft\Update Services\Server\Setup' -Name SQLServerName
```

Erwartet (*sinngemäß*): ein Wert, der `##WID` enthält.

**2. Verbinden**

```powershell
sqlcmd -S 'np:\\.\pipe\MICROSOFT##WID\tsql\query' -E -Q "SELECT name FROM sys.databases"
```

Erwartet (*nicht bestätigt*): `SUSDB` steht unter den Datenbanken. Die Schreibweise mit `np:` ist ungeprüft; funktioniert sie nicht, probiere ohne `np:` und lies `sqlcmd -?`.

**3. Sichern, immer vor einem Eingriff**

```powershell
sqlcmd -S 'np:\\.\pipe\MICROSOFT##WID\tsql\query' -E -Q "BACKUP DATABASE SUSDB TO DISK = 'C:\Backup\SUSDB.bak'"
Get-Item C:\Backup\SUSDB.bak | Select-Object Name, Length, LastWriteTime
```

### Teil 3: Reindex

*(Lerneinheit 9.3, Praxisaufgabe 3)*

Starte währenddessen **keine Synchronisierung**. Prüfe in der Konsole, dass keine läuft.

```powershell
sqlcmd -S 'np:\\.\pipe\MICROSOFT##WID\tsql\query' -E -i C:\Skripte\SUSDBMaint.sql -o C:\Skripte\reindex.log
Get-Content C:\Skripte\reindex.log | Select-Object -First 40
```

Das Protokoll zeigt Meldungen wie `Number of indexes to rebuild: …` und `Executing: ALTER INDEX … REORGANIZE` oder `REBUILD` (so druckt das Skript). Notiere die Zahl der neu aufgebauten Indizes und, falls vorhanden, die Schlusszeilen zu den Statistiken.

### Teil 4: Inhaltsordner verschieben

*(Praxisaufgabe 4)*

```powershell
New-Item -Path 'C:\WSUS_New' -ItemType Directory -Force
cd 'C:\Program Files\Update Services\Tools'
.\WsusUtil.exe movecontent C:\WSUS_New C:\Skripte\movecontent.log
```

`movecontent` kopiert die Dateien; laut Lehrplan bleibt der alte Ordner bestehen. Prüfe den neuen Pfad im IIS-Manager unter *Sites → WSUS-Verwaltung → Content* (virtuelles Verzeichnis, Pfad *Physischer Pfad*).

**Rückbau:**

```powershell
.\WsusUtil.exe movecontent C:\WSUS C:\Skripte\movecontent_zurueck.log
Remove-Item C:\WSUS_New -Recurse -Force
```

Prüfe danach auf `CLIENT01`, dass Updates weiter gefunden werden:

```powershell
(New-Object -ComObject Microsoft.Update.AutoUpdate).DetectNow()
```

## Hinweise

- Die WID akzeptiert nur lokale Verbindungen. Ein Zugriff aus dem Netz geht nicht.
- Beachte die Reihenfolge beim Rückbau: erst zurück verschieben, dann den Zwischenordner löschen.
- `Remove-Item … -Recurse -Force` ist hier unkritisch, weil es nur den eigenen Zwischenordner löscht. Prüfe den Pfad trotzdem, bevor du die Eingabetaste drückst.

## Kontrollfragen

1. Wann sollte ein dedizierter SQL-Server anstelle der WID verwendet werden?
2. Warum reicht der Serverbereinigungs-Assistent allein nicht aus, um die Leistung der WSUS-Konsole zu erhalten?
3. Wofür wird das Kommandozeilenwerkzeug `wsusutil.exe` verwendet?
4. Warum wird die Windows Internal Database laut Microsoft Learn als „deprecated“ geführt, und was bedeutet das für Neuplanungen?

## Musterlösung

<details>
<summary>Antworten und Zielzustand (erst nach dem Versuch öffnen)</summary>

**Zielzustand**

- `C:\Backup\SUSDB.bak` existiert.
- `C:\Skripte\reindex.log` zeigt den Lauf des Skripts.
- Der Inhaltsordner zeigt wieder auf `C:\WSUS`, `C:\WSUS_New` ist gelöscht, `CLIENT01` findet Updates.

**Antworten**

1. Bei vielen Clients, hohem Datenvolumen, Anforderungen an Hochverfügbarkeit oder Sicherung mit vorhandenen SQL-Werkzeugen, bei mehreren Servern, die dieselbe Datenbank brauchen, und in jedem Fall, wenn die WID keine Zukunft hat (Frage 4).
2. Der Assistent entfernt unbenutzte Daten, defragmentiert aber keine Indizes. Dafür dient das Reindex-Skript.
3. Für Verwaltungsaufgaben am WSUS-Server von der Kommandozeile. In dieser Reihe nutzt du `postinstall` (Modul 03), `movecontent` (diese Übung) und `configuressl` (Modul 11). Weitere Unterbefehle liest du in der Hilfe des Werkzeugs nach (*nicht geprüft*).
4. Microsoft führt die WID als deprecated (Modul 01). Für Neuplanungen heißt das, mit einer Datenbank zu planen, die nicht die WID ist, oder den Ausstieg aus WSUS einzuplanen.

</details>

## Erweiterungen

- Stelle die Sicherung auf einem zweiten Server oder in einer zweiten VM wieder her (nur in einer Wegwerf-Umgebung, nie über die laufende SUSDB).
- Lies die Ausgabe von `sqlcmd -S ... -E -Q "SELECT COUNT(*) FROM tbUpdate"` (*Tabellenname nicht bestätigt*) und überlege, was die Zahl zeigt.
