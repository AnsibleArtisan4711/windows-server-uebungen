## Lernziele

Nach dieser Übung kannst du

- erklären, was das Protokoll SMB (Server Message Block) macht und welchen Port es nutzt,
- die Serverrolle „Dateiserver“ über den Server-Manager und über PowerShell installieren bzw. prüfen,
- eine normale und eine versteckte Freigabe erstellen und die Freigabeberechtigung setzen,
- eine Freigabe von einem Domänen-Client als Netzlaufwerk verbinden und die SMB-Verbindung auslesen.

## Voraussetzungen

- Labor laut [README der Reihe](../README.md): `DC1` (Domänencontroller, DNS), `FS1`, `FS2`, `CL1`, alle in der Domäne `corp.example.internal`, statische Adressen, kein DHCP.
- Für dieses Modul genügen `DC1`, `FS1` und `CL1`. `FS2` darf schon laufen.
- Hyper-V-Checkpoint von allen VMs vor dem Start (Name `m00-labor-fertig`).
- Zugriff als Domänenadministrator (`CORP\Administrator`; Annahme: NetBIOS-Name der Domäne ist `CORP`).

## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| **SMB** | Dateifreigabeprotokoll von Windows. Clients greifen über das Netzwerk auf Dateien und Drucker eines Servers zu. |
| **TCP 445** | Standardport von SMB ab Windows 2000, ohne NetBIOS-Umweg. |
| **Dialekt** | Protokollversion (2.0.2, 2.1, 3.0, 3.0.2, 3.1.1). Client und Server handeln die höchste gemeinsame aus. |
| **Freigabe (Share)** | Ordner, den der Server unter einem Namen im Netz anbietet. |
| **Versteckte Freigabe** | Freigabename endet auf `$`. Sie erscheint nicht in der Liste, wenn man den Server durchsucht. Das ist keine Zugriffssicherung. |
| **UNC-Pfad** | `\\Server\Freigabe\Ordner`. |
| **Freigabeberechtigung** | Berechtigung auf der Freigabe selbst. Sie wirkt nur beim Zugriff über das Netzwerk (Modul 02). |

## Aufgabe

Wenn nichts anderes steht, öffne auf dem Server eine **PowerShell als Administrator**. Der Menüweg steht jeweils daneben. Wo es nur einen Weg gibt, steht das dabei.

Hinweis zur Sprache: Namen wie `Domänen-Benutzer` gelten für eine deutsche Oberfläche. Bei englischer Oberfläche heißt die Gruppe `Domain Users`. Die Befehle setzen den Namen in eine Variable, die du anpassen kannst.

### Teil 0: Labor prüfen und einen Testbenutzer anlegen

**1. Namensauflösung und Domäne prüfen (auf FS1)**

```powershell
(Get-CimInstance Win32_ComputerSystem).Domain
Resolve-DnsName dc1.corp.example.internal
Test-ComputerSecureChannel
```

Erwartet (*sinngemäß*): `corp.example.internal`, eine A-Antwort mit `192.168.10.10` und `True`.

**2. Testbenutzer anlegen (auf DC1)**

Menüweg: *Server-Manager → Tools → Active Directory-Benutzer und -Computer → Users → Neu → Benutzer*. PowerShell:

```powershell
$pw = Read-Host 'Passwort für Test_User (nur Labor)' -AsSecureString
New-ADUser -Name 'Test_User' -SamAccountName 'Test_User' `
  -UserPrincipalName 'Test_User@corp.example.internal' `
  -AccountPassword $pw -Enabled $true
```

Kein Passwort in den Befehl schreiben. Die Abfrage mit `Read-Host` hält es aus der Befehlshistorie heraus. Die Benutzer der späteren Module (`IT_Admin`, `Sales_User`) legst du in Modul 02 an.

### Teil 1: SMB ansehen

*(Lerneinheit 1.1)*

**1. SMB-Einstellungen des Servers lesen (auf FS1)**

```powershell
Get-SmbServerConfiguration |
  Select-Object EnableSMB1Protocol, EnableSMB2Protocol, EncryptData, RejectUnencryptedAccess
```

Erwartet (*nicht bestätigt*): `EnableSMB2Protocol` ist `True`. `EnableSMB1Protocol` ist auf einem neu installierten Server 2022 laut Erfahrung nicht aktiv, das gilt es hier zu prüfen. `EncryptData` ist `False`. Notiere deine vier Werte.

`EnableSMB2Protocol` steht für SMB 2 **und** SMB 3. Beide Versionen werden über denselben Schalter geführt.

**2. Port prüfen (auf CL1)**

```powershell
Test-NetConnection -ComputerName FS1 -Port 445
```

Erwartet (*sinngemäß*): `TcpTestSucceeded : True`.

### Teil 2: Die Serverrolle „Dateiserver“

*(Lerneinheit 1.2, Praxisaufgabe 1)*

**1. Rolle prüfen und installieren (auf FS1)**

Menüweg: *Server-Manager → Verwalten → Rollen und Features hinzufügen → Rollenbasierte Installation → FS1 → Datei- und Speicherdienste → Datei- und iSCSI-Dienste → Dateiserver*. PowerShell:

```powershell
Get-WindowsFeature FS-FileServer
Install-WindowsFeature -Name FS-FileServer -IncludeManagementTools
Get-WindowsFeature FS-FileServer
```

Erwartet (*nicht bestätigt*): Der Rollendienst `FS-FileServer` ist bei einer Standardinstallation möglicherweise schon installiert. Dann meldet `Install-WindowsFeature` keine Änderung. Das ist in Ordnung, die Aufgabe ist dann erfüllt. Die Spalte `Install State` zeigt zum Schluss `Installed`.

### Teil 3: Freigaben erstellen

*(Lerneinheit 1.3, Praxisaufgabe 2)*

**1. Ordner anlegen (auf FS1)**

```powershell
New-Item -Path 'C:\Shares\Public' -ItemType Directory -Force
Set-Content -Path 'C:\Shares\Public\Willkommen.txt' -Value 'Dateiserver FS1, Modul 01'
```

Der Ordner liegt auf `C:`. Mit einer zweiten virtuellen Festplatte (VHDX) geht es genauso. Es zählt nur der Pfad.

**2. Versteckte Freigabe `Public$` mit Leserecht für Domänen-Benutzer**

Menüweg: *Server-Manager → Datei-/Speicherdienste → Freigaben → Aufgaben → Neue Freigabe → SMB-Freigabe – Schnell*, Pfad `C:\Shares\Public`, Name `Public$`, bei den Berechtigungen den Zugriff für die Gruppe `Domänen-Benutzer` auf *Lesen* setzen. PowerShell:

```powershell
$DomUsers = 'CORP\Domänen-Benutzer'   # englisch: 'CORP\Domain Users'
New-SmbShare -Name 'Public$' -Path 'C:\Shares\Public' -ReadAccess $DomUsers
```

Das `$` im Namen verlangt einfache Anführungszeichen. In doppelten würde PowerShell `$'` als Variable lesen.

**3. Freigabe prüfen**

```powershell
Get-SmbShare
Get-SmbShareAccess -Name 'Public$'
```

Erwartet (*sinngemäß*): `Public$` steht in der Liste neben den Standardfreigaben `ADMIN$`, `C$` und `IPC$`. `Get-SmbShareAccess` zeigt `CORP\Domänen-Benutzer` mit `Read`.

### Teil 4: Vom Client verbinden

*(Praxisaufgabe 3)*

**1. Als Domänenbenutzer an CL1 anmelden**

Melde dich an `CL1` als `CORP\Test_User` an.

**2. Server durchsuchen: die Freigabe ist nicht zu sehen**

```powershell
net view \\FS1
net view \\FS1 /all
```

Erwartet (*sinngemäß*): Die erste Liste enthält `Public$` nicht, die zweite mit `/all` schon. Das `$` blendet die Freigabe nur aus der Liste aus.

**3. Als Netzlaufwerk verbinden**

Menüweg: *Explorer → Dieser PC → Netzlaufwerk verbinden*, Laufwerk `Z:`, Ordner `\\FS1\Public$`, „Verbindung bei Anmeldung wiederherstellen“ aktiv. PowerShell:

```powershell
New-PSDrive -Name Z -PSProvider FileSystem -Root '\\FS1\Public$' -Persist
Get-Content Z:\Willkommen.txt
```

Erwartet: Der Inhalt der Datei erscheint.

**4. Schreiben ausprobieren**

```powershell
New-Item -Path Z:\test-schreiben.txt -ItemType File
```

Erwartet (*sinngemäß*): Zugriff verweigert, denn die Freigabe erlaubt nur Lesen.

**5. SMB-Verbindung auslesen (auf CL1)**

```powershell
Get-SmbConnection | Select-Object ServerName, ShareName, Dialect, Encrypted
```

Erwartet (*nicht bestätigt*): `FS1`, `Public$` und als Dialekt `3.1.1`. Windows 11 und Server 2022 handeln laut Erfahrung den höchsten gemeinsamen Dialekt aus. Notiere, was du siehst.

## Hinweise

- Der Zugriff über das Netz wirkt als **Schnittmenge** aus Freigabe- und NTFS-Berechtigung. `C:\Shares\Public` erbt die NTFS-Rechte von `C:\`. Dort dürfen normale Benutzer lesen, deshalb klappt das Lesen. Mit den NTFS-Rechten befasst sich Modul 02.
- Hinter `Public$` steckt kein Schutz. Wer den Namen kennt, kommt hin. Schützen kann nur die Berechtigung.
- Bleibt das Laufwerk `Z:` nach einem Neustart stehen und der Server ist aus, zeigt der Explorer das Laufwerk mit einem roten Kreuz. Das ist harmlos, der Server ist nur nicht erreichbar.
- Es gibt `ADMIN$`, `C$` und `IPC$` schon, bevor du etwas freigibst. Das sind die administrativen Freigaben.

## Kontrollfragen

1. Welchen TCP-Port nutzt das moderne SMB-Protokoll standardmäßig?
2. Wie unterscheidet sich SMBv3 von älteren Versionen in Bezug auf Sicherheit im Netzwerk?
3. Warum ist das Anhängen eines `$`-Zeichens an den Freigabenamen in Windows-Netzwerken nützlich, und was leistet es nicht?

## Musterlösung

<details>
<summary>Antworten und Zielzustand (erst nach dem Versuch öffnen)</summary>

**Zielzustand**

- `FS1` hat die Rolle `FS-FileServer` (Status `Installed`).
- Die Freigabe `Public$` zeigt auf `C:\Shares\Public`, Berechtigung `CORP\Domänen-Benutzer: Read`.
- `CL1` hat `Z:` mit `\\FS1\Public$` verbunden, `Test_User` kann lesen, aber nicht schreiben.

**Antworten**

1. TCP **445**. Ältere Windows-Versionen nutzten zusätzlich NetBIOS über TCP 139.
2. SMB 3 bringt Verschlüsselung der Übertragung (pro Freigabe oder für den ganzen Server) und Signierung. Ab 3.1.1 schützt die „Pre-Authentication Integrity“ vor Manipulation beim Verbindungsaufbau. SMB 1 hat nichts davon und gilt als unsicher.
3. Die Freigabe taucht beim Durchsuchen des Servers nicht in der Liste auf. Sie ist nicht geschützt: Wer den UNC-Pfad kennt, kann zugreifen, sofern die Berechtigungen es erlauben.

</details>

## Erweiterungen

- Verschlüsselung für die Freigabe einschalten und die Verbindung neu aufbauen: `Set-SmbShare -Name 'Public$' -EncryptData $true -Force`, danach auf `CL1` die Verbindung trennen (`Remove-PSDrive Z`) und wieder verbinden. Prüfe `Encrypted` in `Get-SmbConnection` (*nicht bestätigt*).
- Eine zweite, normal sichtbare Freigabe `Doku` anlegen und im Server-Manager den Unterschied der beiden Freigaben in der Liste ansehen.
