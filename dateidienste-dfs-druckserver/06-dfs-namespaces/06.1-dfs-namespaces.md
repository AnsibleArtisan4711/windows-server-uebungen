# 06.1 DFS-Namespaces: domänenbasierter Namespace mit zwei Ordnerzielen

| | |
|---|---|
| **Modul** | 06 Distributed File System (DFS): Namespaces |
| **Stufe** | Aufbau |
| **Geschätzte Zeit** | 6 bis 8 Stunden (Schätzung; Lehrplan: 10 UE zu 45 Minuten = 7,5 Stunden) |
| **Werkzeuge** | DFS-Verwaltung, Windows PowerShell (Modul DFSN), `dfsdiag`, Windows-Explorer |
| **Vorwissen** | Module 01 und 02 abgeschlossen, `FS2` ist installiert und in der Domäne |

> [!WARNING]
> **Stand der Prüfung: Entwurf, nicht im Labor ausgeführt.** Die Cmdlets `New-DfsnRoot` (Typ `DomainV2`), `New-DfsnFolder`, `New-DfsnFolderTarget` und die Voraussetzung „Ordner anlegen und freigeben, dann `New-DfsnRoot`“ wurden am 11.11.2026 gegen die Microsoft-Learn-Dokumentation geprüft. **Nicht geprüft:** `New-DfsnRootTarget`, `Set-DfsnRoot`, die Einstellung der Verweisreihenfolge per PowerShell, die Registerkarte *DFS* auf dem Client (der Lehrplan nennt ihre Bezeichnung selbst *nicht bestätigt*) und die erwarteten Ausgaben.

## Lernziele

Nach dieser Übung kannst du

- den Unterschied zwischen domänenbasierten und eigenständigen (Standalone) Namespaces erklären,
- die Rolle „DFS-Namespaces“ installieren und einen domänenbasierten Namespace mit zwei Namespaceservern anlegen,
- Ordner und Ordnerziele hinzufügen und Verweise (Referrals) konfigurieren,
- am Client prüfen, mit welchem Ordnerziel er verbunden ist.

## Voraussetzungen

- Module 01 und 02 abgeschlossen. Freigabe `\\FS1\Unternehmensdaten` mit Ordner `Vertrieb`. Checkpoint `m05-ende`.
- `FS2` ist installiert, hat die statische Adresse `192.168.10.21`, DNS `192.168.10.10` und ist Mitglied der Domäne.
- `DC1` läuft (ohne ihn funktioniert ein domänenbasierter Namespace nicht).

## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| **DFS-Namespace** | Einheitlicher Namensraum, der Freigaben mehrerer Server unter einem Pfad zusammenführt (`\\corp.example.internal\GlobalFiles`). |
| **Domänenbasiert** | Konfiguration liegt in Active Directory. Mehrere Namespaceserver möglich, ausfallsicher. Pfad beginnt mit dem Domänennamen. |
| **Eigenständig (Standalone)** | Konfiguration liegt nur auf einem Server. Pfad beginnt mit dem Servernamen. Fällt der Server aus, ist der Namespace weg (außer in einem Cluster). |
| **Namespaceserver** | Server, der den Namespace-Stamm (Root) bereitstellt und Verweise ausgibt. |
| **Ordner / Ordnerziel** | Ordner im Namespace verweisen auf ein oder mehrere Ziele (echte Freigaben). |
| **Verweis (Referral)** | Liste der Ziele, die ein Namespaceserver dem Client gibt. |

## Testumgebung

| Gerät | Rolle in Modul 06 | Adresse |
|---|---|---|
| DC1 | Active Directory, DNS (ohne ihn kein Namespace) | 192.168.10.10 |
| FS1 | Namespaceserver 1, Ordnerziel `Vertrieb` | 192.168.10.20 |
| FS2 | Namespaceserver 2, zweites Ordnerziel | 192.168.10.21 |
| CL1 | Zugriff testen | 192.168.10.50 |

## Aufgabe

Zielbild:

```text
\\corp.example.internal\GlobalFiles          (Namespaceserver: FS1 und FS2)
└── Vertrieb ──► \\FS1\Unternehmensdaten\Vertrieb
             └─► \\FS2\Vertrieb_Replika
```

### Teil 1: Rolle installieren (auf FS1 und FS2)

*(Lerneinheit 6.1, Praxisaufgabe 1)*

Menüweg: *Server-Manager → Rollen und Features hinzufügen → Datei- und iSCSI-Dienste → DFS-Namespaces*. PowerShell (auf beiden Servern):

```powershell
Install-WindowsFeature -Name FS-DFS-Namespace, RSAT-DFS-Mgmt-Con
Get-WindowsFeature FS-DFS-Namespace, RSAT-DFS-Mgmt-Con
```

Die Namen `FS-DFS-Namespace` (Rolle) und `RSAT-DFS-Mgmt-Con` (Verwaltungswerkzeuge) stehen so in der Microsoft-Dokumentation. Erwartet: beide `Installed`.

### Teil 2: Namespace erstellen

*(Lerneinheit 6.2, Praxisaufgabe 2)*

**1. Stammordner und Stammfreigabe anlegen (auf FS1 und auf FS2)**

Der Namespace-Stamm braucht auf jedem Namespaceserver eine Freigabe. Die DFS-Verwaltung legt sie beim Erstellen meist selbst an. Mit PowerShell machst du es vorher selbst (so zeigt es die Microsoft-Dokumentation):

```powershell
New-Item -Path 'C:\DFSRoots\GlobalFiles' -ItemType Directory -Force
New-SmbShare -Name 'GlobalFiles' -Path 'C:\DFSRoots\GlobalFiles' -ReadAccess 'CORP\Domänen-Benutzer'   # englisch: 'CORP\Domain Users'
```

**2. Namespace anlegen (auf FS1)**

Menüweg: *Server-Manager → Tools → DFS-Verwaltung → Namespaces → Neuer Namespace*, Server `FS1`, Name `GlobalFiles`, *Domänenbasierter Namespace* (Modus *Windows Server 2008*), erstellen. PowerShell:

```powershell
New-DfsnRoot -Path '\\corp.example.internal\GlobalFiles' -TargetPath '\\FS1\GlobalFiles' -Type DomainV2
Get-DfsnRoot
```

Erwartet (*sinngemäß*): ein Eintrag mit Pfad `\\corp.example.internal\GlobalFiles` und Typ `Domain V2`.

**3. FS2 als zweiten Namespaceserver hinzufügen (auf FS1)**

Menüweg: *DFS-Verwaltung → Rechtsklick auf den Namespace → Namespaceserver hinzufügen*, `FS2`. PowerShell (*`New-DfsnRootTarget` nicht gegen die Dokumentation geprüft*):

```powershell
New-DfsnRootTarget -Path '\\corp.example.internal\GlobalFiles' -TargetPath '\\FS2\GlobalFiles'
Get-DfsnRootTarget -Path '\\corp.example.internal\GlobalFiles'
```

Erwartet: zwei Namespaceserver, `FS1` und `FS2`, beide `Online`.

### Teil 3: Ordner und erstes Ordnerziel

*(Lerneinheit 6.3, Praxisaufgabe 3)*

**1. Ordner `Vertrieb` anlegen und mit `FS1` verknüpfen (auf FS1)**

Menüweg: *DFS-Verwaltung → Namespace → Neuer Ordner*, Name `Vertrieb`, *Hinzufügen* → Pfad `\\FS1\Unternehmensdaten\Vertrieb`. PowerShell:

```powershell
New-DfsnFolder -Path '\\corp.example.internal\GlobalFiles\Vertrieb' `
  -TargetPath '\\FS1\Unternehmensdaten\Vertrieb'
Get-DfsnFolderTarget -Path '\\corp.example.internal\GlobalFiles\Vertrieb'
```

**2. Zugriff von CL1 testen (als `CORP\Sales_User`)**

```powershell
Get-ChildItem '\\corp.example.internal\GlobalFiles\Vertrieb'
```

Erwartet: der Inhalt von `\\FS1\Unternehmensdaten\Vertrieb`. Im Explorer: Adressleiste `\\corp.example.internal\GlobalFiles`, der Ordner `Vertrieb` ist sichtbar. Hinweis: Mit Access-Based Enumeration auf der Freigabe `Unternehmensdaten` sieht `Sales_User` hier `Vertrieb` (er hat Rechte), im Namespace-Stamm aber nur die Ordner, die als DFS-Ordner angelegt sind.

### Teil 4: Zweites Ordnerziel und Verweise

*(Praxisaufgabe 4)*

**1. Ordner und Freigabe auf FS2 anlegen**

Die Rechte am Zielordner setzt der Lehrplan so: Freigabe *Jeder: Vollzugriff*, NTFS *Domänen-Benutzer: Ändern*.

```powershell
New-Item -Path 'C:\Shares\Vertrieb_Replika' -ItemType Directory -Force
New-SmbShare -Name 'Vertrieb_Replika' -Path 'C:\Shares\Vertrieb_Replika' -FullAccess 'Jeder'   # englisch: 'Everyone'
icacls 'C:\Shares\Vertrieb_Replika' /grant 'CORP\Domänen-Benutzer:(OI)(CI)M'   # englisch: 'CORP\Domain Users'
```

**2. Zweites Ordnerziel hinzufügen (auf FS1)**

Menüweg: *DFS-Verwaltung → Ordner `Vertrieb` → Ordnerziel hinzufügen*, Pfad `\\FS2\Vertrieb_Replika`. Die Frage „Replikationsgruppe erstellen?“ beantwortest du mit **Nein** (kommt in Modul 07). PowerShell:

```powershell
New-DfsnFolderTarget -Path '\\corp.example.internal\GlobalFiles\Vertrieb' `
  -TargetPath '\\FS2\Vertrieb_Replika'
Get-DfsnFolderTarget -Path '\\corp.example.internal\GlobalFiles\Vertrieb'
```

Erwartet: zwei Ziele, beide `Online`.

**3. Verweisreihenfolge auf „Zufällige Reihenfolge“ stellen**

Menüweg: *DFS-Verwaltung → Namespace → Rechtsklick auf Namespace-Stamm oder Ordner → Eigenschaften → Reiter Verweise → Sortiermethode → Zufällige Reihenfolge* (Bezeichnungen *nicht bestätigt*). Die Einstellung per PowerShell ist hier bewusst nicht angegeben, weil Parameter und Wirkung nicht geprüft sind.

**4. Auf CL1 prüfen, mit welchem Ziel der Client verbunden ist**

Öffne `\\corp.example.internal\GlobalFiles\Vertrieb` im Explorer, dann *Rechtsklick → Eigenschaften → Reiter DFS* (Menünamen *nicht bestätigt*). Dort steht das aktive Ziel. Als Alternativen:

```powershell
dfsdiag /testreferral /DFSpath:\\corp.example.internal\GlobalFiles\Vertrieb /full
```

`dfsdiag` wird mit den DFS-Verwaltungswerkzeugen installiert (auf `CL1` müsste das Windows-Funktionsfeature „RSAT: Dateidienste-Tools“ aktiv sein, *nicht bestätigt*). Auf den Servern ist es vorhanden. Trenne die Verbindung (`net use * /delete` bzw. Explorer neu starten) und prüfe mehrmals. Notiere, wie oft `FS1` und wie oft `FS2` erscheint.

Ohne Replikation ist das Ziel auf `FS2` noch leer (`C:\Shares\Vertrieb_Replika`). Der Test dient nur der Verweisauswahl.

## Hinweise

- Ein domänenbasierter Namespace ist nur so erreichbar wie die Domänencontroller. Im Labor gibt es nur `DC1`. Fällt er aus, kann kein Client mehr einen domänenbasierten Pfad auflösen (in Modul 12 relevant).
- Clients **merken sich** Verweise im Cache für eine festgelegte Zeit (TTL). Eine Änderung am Namespace wirkt deshalb nicht sofort. Auf dem Client hilft `dfsutil /pktflush` (*nicht bestätigt*, `dfsutil` gehört zu den DFS-Werkzeugen).
- Das Löschen eines Ordnerziels in der DFS-Verwaltung löscht **keine Daten**. Es entfernt nur den Verweis.
- Der Stamm `\\corp.example.internal\GlobalFiles` braucht auf **jedem** Namespaceserver eine Freigabe `GlobalFiles` und eine funktionierende Namensauflösung. Ohne DNS auf `DC1` scheitert alles.
- Die Rechte am Zielordner auf `FS2` weichen vom Ordner `Vertrieb` auf `FS1` ab (AGDLP). Das ist im Lehrplan so festgelegt. In Modul 07 und 12 gleichst du sie an.

## Kontrollfragen

1. Warum bietet ein domänenbasierter Namespace eine höhere Ausfallsicherheit als ein eigenständiger (Standalone) Namespace?
2. Wie entscheiden DFS-Clients, zu welchem Zielserver sie sich verbinden, wenn mehrere Ziele für denselben Ordner existieren?
3. Was geschieht mit den echten Dateidaten auf der Festplatte, wenn man ein DFS-Ordnerziel in der Verwaltungskonsole löscht?

## Musterlösung

<details>
<summary>Antworten und Zielzustand (erst nach dem Versuch öffnen)</summary>

**Zielzustand**

- `FS1` und `FS2` haben die Rolle `FS-DFS-Namespace`.
- Der Namespace `\\corp.example.internal\GlobalFiles` ist domänenbasiert und hat zwei Namespaceserver.
- Der DFS-Ordner `Vertrieb` hat zwei Ziele (`\\FS1\Unternehmensdaten\Vertrieb`, `\\FS2\Vertrieb_Replika`), Reihenfolge zufällig. Der Client erreicht beide, Daten gibt es nur auf `FS1`.

**Antworten**

1. Die Konfiguration steht in Active Directory und kann von mehreren Namespaceservern bereitgestellt werden. Fällt einer aus, liefert der andere die Verweise. Ein eigenständiger Namespace hängt an einem einzigen Server.
2. Der Namespaceserver gibt eine geordnete Liste (Verweis) zurück. Die Reihenfolge bestimmt die Einstellung: standardmäßig die Ziele im **eigenen Active-Directory-Standort** zuerst, bei der Einstellung „Zufällige Reihenfolge“ gemischt, oder nach niedrigsten Kosten. Der Client probiert die Ziele der Reihe nach durch.
3. Nichts. Es verschwindet nur der Verweis im Namespace. Der Ordner und seine Dateien auf dem Server bleiben unverändert.

</details>

## Erweiterungen

- Setze die Priorität für das Ziel auf `FS1` auf „Erste unter allen Zielen“ (Ordnerziel → Eigenschaften → Erweitert; `New-DfsnFolderTarget` hat die Parameter `-ReferralPriorityClass` und `-ReferralPriorityRank`) und prüfe, dass der Client nun immer `FS1` bekommt.
- Lege einen eigenständigen Namespace `\\FS1\Standalone` an und vergleiche den Pfad und die Verwaltung mit dem domänenbasierten Namespace.
- Setze den Ordnerziel-Zustand von `FS1` auf *Offline* (`Set-DfsnFolderTarget -State Offline`) und beobachte, wohin der Client verwiesen wird. Setze ihn danach wieder auf *Online*.
