## Lernziele

Nach dieser Übung kannst du

- Offlinedateien auf Server (Zwischenspeicherung der Freigabe) und Client (Offlinedateien aktivieren) konfigurieren,
- einen Ordner „immer offline verfügbar“ machen und die Synchronisation nach einer Netzunterbrechung prüfen,
- das Prinzip von BranchCache (Hosted Cache und Distributed Cache) erklären.

## Voraussetzungen

- Modul 07 abgeschlossen, Checkpoint `m07-ende`. `Sales_User` ist Mitglied in `G_Sales`.
- Freigabe `\\FS1\Unternehmensdaten` mit dem Ordner `Vertrieb`.
- Hyper-V-Host: Zugriff auf die Einstellungen der VM `CL1` (Netzwerkkarte trennen).

## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| **Offlinedateien** | Der Client speichert Kopien von Dateien einer Freigabe lokal und arbeitet damit weiter, wenn die Verbindung fehlt. |
| **Client Side Caching (CSC)** | Technischer Name der Funktion. Die Zwischenspeicherung stellt der Server pro Freigabe ein. |
| **Manuell / Dokumente / Programme / BranchCache / Keine** | Zwischenspeicher-Modi einer Freigabe (`CachingMode`). `Documents` speichert automatisch jede Datei, die der Benutzer öffnet. |
| **Synchronisierungscenter** | Ort in der Systemsteuerung für Synchronisation und Konflikte. |
| **BranchCache** | Technik, die Inhalte von Dateiservern in einer Außenstelle zwischenspeichert, damit sie nicht mehrfach über die WAN-Leitung laufen. |
| **Hosted Cache** | Ein Server in der Außenstelle hält den Zwischenspeicher für alle Clients. |
| **Distributed Cache** | Die Clients der Außenstelle tauschen untereinander den Zwischenspeicher aus. Kein Server nötig. |

## Aufgabe

### Teil 1: Zwischenspeicherung auf dem Server

*(Lerneinheit 8.1, Praxisaufgabe 1)*

Menüweg: *Server-Manager → Datei-/Speicherdienste → Freigaben → Rechtsklick auf `Unternehmensdaten` → Eigenschaften → Einstellungen → Offlinedateien (Zwischenspeicherung) → „Nur die von Benutzern angegebenen Dateien und Programme sind offline verfügbar“ / „Alle von Benutzern ohne Zwischenspeicherung geöffneten Dateien und Programme sind automatisch offline verfügbar“*. Wähle die zweite Einstellung (Bezeichnungen *nicht bestätigt*). PowerShell (auf FS1):

```powershell
Set-SmbShare -Name 'Unternehmensdaten' -CachingMode Documents -Force
Get-SmbShare -Name 'Unternehmensdaten' | Select-Object Name, CachingMode
```

Erwartet: `CachingMode` steht auf `Documents`. Die Einstellung `Manual` entspricht „nur vom Benutzer angegebene Dateien“, `Documents` „alle geöffneten Dateien automatisch“.

### Teil 2: Client konfigurieren und testen

*(Praxisaufgabe 2)*

**1. Offlinedateien auf CL1 aktivieren**

Menüweg: *Systemsteuerung → Synchronisierungscenter → Offlinedateien verwalten → Offlinedateien aktivieren* (Menünamen *nicht bestätigt*). Starte `CL1` neu, wenn Windows es verlangt. PowerShell (*nicht bestätigt*):

```powershell
(Get-CimInstance -ClassName Win32_OfflineFilesCache).Enable($true)  # Neustart erforderlich
```

Dieser Aufruf nutzt die WMI-Klasse `Win32_OfflineFilesCache`. Sie ist hier ein Vorschlag. Die Systemsteuerung ist der Hauptweg.

**2. Ordner „Immer offline verfügbar“ machen (als `CORP\Sales_User`)**

Öffne `\\FS1\Unternehmensdaten`, Rechtsklick auf `Vertrieb` → *Immer offline verfügbar*. Warte, bis die Synchronisation fertig ist. Im Synchronisierungscenter steht der Zustand.

**3. Netz trennen (auf dem Hyper-V-Host)**

Menüweg: *Hyper-V-Manager → CL1 → Einstellungen → Netzwerkadapter → Virtueller Switch: Nicht verbunden*. PowerShell (auf dem Host, Name des Adapters prüfen):

```powershell
Get-VMNetworkAdapter -VMName CL1
Disconnect-VMNetworkAdapter -VMName CL1
```

**4. Offline arbeiten (auf CL1)**

Öffne `Test.txt` im Ordner `Vertrieb` (jetzt über den Offlinezugriff), ändere den Inhalt auf `Offline bearbeitet` und speichere. Der Explorer zeigt `Offline`.

**5. Netz wieder verbinden und synchronisieren (auf dem Host)**

```powershell
Connect-VMNetworkAdapter -VMName CL1 -SwitchName 'vSwitch-File-Privat'
```

Auf `CL1`: *Synchronisierungscenter → Offlinedateien → Synchronisieren*. Prüfe auf dem Server:

```powershell
Get-Content 'C:\Shares\Unternehmensdaten\Vertrieb\Test.txt'
```

Erwartet: `Offline bearbeitet`.

**6. Konflikt provozieren (optional)**

Trenne das Netz erneut. Ändere `Test.txt` auf `CL1` offline. Ändere dieselbe Datei auf dem Server (`Set-Content`). Verbinde das Netz und synchronisiere. Das Synchronisierungscenter meldet einen Konflikt. Wähle *Beide Versionen beibehalten* und sieh dir das Ergebnis an.

### Teil 3: BranchCache (Theorie, Lerneinheit 8.2)

Beantworte die Kontrollfragen 2 und 3 schriftlich, bevor du die Musterlösung öffnest. Ordne die beiden Modi einer Skizze zu:

```text
Hosted Cache:        Außenstelle:  Clients ──► Hosted-Cache-Server ──(WAN)──► Zentrale (Dateiserver)
Distributed Cache:   Außenstelle:  Client A ◄──► Client B ◄──► Client C ──(WAN)──► Zentrale (Dateiserver)
```

## Hinweise

- Die Zwischenspeicherung ist eine **Einstellung der Freigabe** am Server. Der Client braucht zusätzlich seine eigene Aktivierung.
- Offlinedateien zeigen die **zuletzt synchronisierte** Version. Ändert jemand die Datei auf dem Server, merkt es der Offline-Client erst nach der Synchronisation.
- Wer den Ordner offline bearbeitet, braucht die NTFS-Rechte aus Modul 02 auch beim späteren Hochladen. Fehlen sie, entsteht ein Synchronisationsfehler.
- Offlinedateien und der DFS-Namespace passen zusammen, wenn das Ordnerziel dasselbe bleibt. Bei wechselnden Zielen (Zufallsverweis) ist das Verhalten *nicht bestätigt*. Teste deshalb in diesem Modul mit dem UNC-Pfad des Servers.

## Kontrollfragen

1. Welche Konflikte können bei der Nutzung von Offlinedateien auftreten, und wie werden sie im Sync-Center gelöst?
2. Was ist der Hauptunterschied zwischen dem „Hosted Cache“-Modus und dem „Distributed Cache“-Modus bei BranchCache?
3. Warum ist BranchCache in WAN-Szenarien besonders ressourcenschonend?

## Musterlösung

<details>
<summary>Antworten und Zielzustand (erst nach dem Versuch öffnen)</summary>

**Zielzustand**

- `Unternehmensdaten` hat `CachingMode = Documents`.
- `CL1` hat Offlinedateien aktiv. `Vertrieb` ist „immer offline verfügbar“.
- Die Änderung, die offline entstand, steht nach der Synchronisation auf dem Server.

**Antworten**

1. Konflikt: Dieselbe Datei wurde offline auf dem Client **und** online auf dem Server geändert. Weitere Fälle: Datei gelöscht und geändert, oder zwei Dateien gleichen Namens. Im Synchronisierungscenter wählt man *Meine Version behalten*, *Serverversion behalten* oder *Beide behalten* (Umbenennung mit Zusatz).
2. Beim **Hosted Cache** hält ein dedizierter Server in der Außenstelle den Zwischenspeicher. Beim **Distributed Cache** halten die Clients den Zwischenspeicher selbst und tauschen ihn im lokalen Netz aus. Der erste braucht einen Server, der zweite nicht, ist aber nur so verfügbar wie die Clients.
3. Der erste Client holt die Datei über das WAN. Weitere Clients derselben Außenstelle bekommen sie aus dem lokalen Zwischenspeicher. Das WAN trägt jede Datei nur einmal. Das spart Bandbreite, und die Zentrale wird entlastet.

</details>

## Erweiterungen

- **BranchCache für Netzwerkdateien (unerprobt):** Installiere auf `FS1` das Feature „BranchCache für Netzwerkdateien“ (Name im Server-Manager: *Datei- und iSCSI-Dienste → BranchCache für Netzwerkdateien*), stelle `Set-SmbShare -Name 'Unternehmensdaten' -CachingMode BranchCache` ein und aktiviere auf `CL1` mit `Enable-BCDistributed` den Distributed-Cache-Modus (*alle drei Schritte nicht bestätigt*; für die Hash-Veröffentlichung ist zusätzlich eine Gruppenrichtlinie nötig). Mit nur einem Client lässt sich der Gewinn im Labor nicht zeigen.
- Stelle die Freigabe auf `Manual` zurück und prüfe, dass `CL1` nicht mehr automatisch Dateien zwischenspeichert.
- Lies den Cache auf `CL1` aus (Synchronisierungscenter → Offlinedateien → Datenträgerauslastung) und notiere die Größe.
