## Lernziele

Nach dieser Übung kannst du

- den Ressourcen-Manager für Dateiserver (FSRM) installieren,
- ein hartes und ein weiches Kontingent einrichten und den Unterschied zeigen,
- ein Kontingent mit automatischer Anwendung auf Unterordner (Auto-Apply) anlegen,
- einen aktiven Dateiprüfungsfilter erstellen und seine Wirkung am Client prüfen.

## Voraussetzungen

- Modul 02 abgeschlossen. Checkpoint `m03-ende` oder `m02-ende`.
- Auf `FS1`: `C:\Shares\Unternehmensdaten\Vertrieb`.
- Auf `CL1`: Anmeldung als `Sales_User` möglich.

## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| **FSRM** | File Server Resource Manager. Rollendienst mit Kontingenten, Dateiprüfung, Klassifizierung, Berichten. |
| **Hartes Kontingent** | Wird die Grenze erreicht, kann nichts mehr gespeichert werden. |
| **Weiches Kontingent** | Wird die Grenze überschritten, löst FSRM Meldungen aus, blockiert aber nicht. |
| **Schwellenwert** | Prozentwert der Grenze (z. B. 85 %), bei dem FSRM eine Aktion auslöst (E-Mail, Ereignisprotokoll, Befehl). |
| **Auto-Apply-Kontingent** | Kontingent auf einem Elternordner, das für jeden Unterordner (auch künftige) ein eigenes Kontingent anlegt. |
| **Dateiprüfung (File Screen)** | Blockiert das **Speichern** bestimmter Dateitypen (nach Dateiname). |
| **Aktiv / passiv** | Ein aktiver Filter blockiert. Ein passiver Filter meldet nur. |

## Testumgebung

| Gerät | Rolle in Modul 04 | Adresse |
|---|---|---|
| FS1 | FSRM, Kontingente, Filter | 192.168.10.20 |
| CL1 | Verhalten prüfen als `Sales_User` | 192.168.10.50 |

## Aufgabe

### Teil 1: FSRM installieren (auf FS1)

*(Lerneinheit 4.1, Praxisaufgabe 1)*

Menüweg: *Server-Manager → Verwalten → Rollen und Features hinzufügen → Datei- und Speicherdienste → Datei- und iSCSI-Dienste → Ressourcen-Manager für Dateiserver*. PowerShell:

```powershell
Install-WindowsFeature -Name FS-Resource-Manager -IncludeManagementTools
Get-WindowsFeature FS-Resource-Manager
```

Erwartet (*sinngemäß*): `Installed`. Starte die Verwaltung über *Server-Manager → Tools → Ressourcen-Manager für Dateiserver*. Der Feature-Name `FS-Resource-Manager` ist der übliche (*nicht bestätigt*), prüfe ihn mit `Get-WindowsFeature *Resource*`.

### Teil 2: Kontingente

*(Lerneinheit 4.2, Praxisaufgabe 2)*

**1. Hartes Kontingent 500 MB auf `Vertrieb`**

Menüweg: *FSRM → Kontingentverwaltung → Kontingente → Aktionen → Kontingent erstellen*, Pfad `C:\Shares\Unternehmensdaten\Vertrieb`, *Benutzerdefinierte Kontingenteigenschaften definieren*, Grenzwert 500 MB, *Hartes Kontingent*. PowerShell:

```powershell
New-FsrmQuota -Path 'C:\Shares\Unternehmensdaten\Vertrieb' -Size 500MB
Get-FsrmQuota -Path 'C:\Shares\Unternehmensdaten\Vertrieb'
```

Ohne `-SoftLimit` ist das Kontingent hart (*nicht bestätigt*, in der Ausgabe `SoftLimit` prüfen: `False`).

**2. Home-Ordner anlegen**

```powershell
New-Item 'C:\Shares\Home\IT_Admin'   -ItemType Directory -Force
New-Item 'C:\Shares\Home\Sales_User' -ItemType Directory -Force
```

**3. Weiches Kontingent mit automatischer Anwendung auf Unterordner**

Menüweg: *FSRM → Kontingente → Auto-Apply-Kontingent erstellen*, Pfad `C:\Shares\Home`, *Benutzerdefinierte Eigenschaften*, Grenzwert z. B. 100 MB (die Größe ist deine Wahl, im Lehrplan nicht festgelegt), *Weiches Kontingent*, Schwellenwert 85 % mit Eintrag im Ereignisprotokoll. PowerShell (*Parameter `-Threshold` nicht bestätigt*):

```powershell
$schwelle = New-FsrmQuotaThreshold -Percentage 85 `
  -Action (New-FsrmAction -Type Event -EventType Warning -Body 'Home-Kontingent 85 Prozent erreicht')
New-FsrmAutoQuota -Path 'C:\Shares\Home' -Size 100MB -SoftLimit -Threshold $schwelle
```

**4. Prüfen**

```powershell
Get-FsrmAutoQuota
Get-FsrmQuota | Select-Object Path, Size, SoftLimit, Usage
```

Erwartet (*sinngemäß*): ein Auto-Apply-Eintrag für `C:\Shares\Home` und je ein Kontingent für `IT_Admin` und `Sales_User` mit 100 MB, `SoftLimit = True`.

**5. Beide Kontingente testen (auf FS1)**

Erzeuge eine Datei im Home-Ordner, die das weiche Kontingent überschreitet, und eine im Vertrieb, die das harte überschreitet:

```powershell
fsutil file createnew 'C:\Shares\Home\Sales_User\gross.bin' 125829120      # 120 MB
fsutil file createnew 'C:\Shares\Unternehmensdaten\Vertrieb\gross.bin' 629145600   # 600 MB
```

Erwartet (*nicht bestätigt*): Die erste Datei wird angelegt (weich), im Ereignisprotokoll *Anwendungs- und Dienstprotokolle* steht eine FSRM-Meldung zum Überschreiten. Die zweite Datei lässt sich nicht anlegen oder die Prüfung meldet zu wenig Platz (hart). Notiere die Meldung wörtlich. Lösche die erste Datei danach:

```powershell
Remove-Item 'C:\Shares\Home\Sales_User\gross.bin'
```

> Das harte Kontingent auf `Vertrieb` wird in Modul 07 vor der Replikation wieder entfernt.

### Teil 3: Dateiprüfung

*(Lerneinheit 4.3, Praxisaufgabe 3)*

**1. Vorlage suchen**

```powershell
Get-FsrmFileScreenTemplate | Select-Object Name
```

Die Vorlage „Audio- und Videodateien blockieren“ heißt je nach Sprache anders (englisch `Block Audio and Video Files`). Kopiere den Namen aus der Ausgabe.

**2. Aktiven Filter auf `C:\Shares` anlegen**

Menüweg: *FSRM → Dateiprüfungsverwaltung → Dateiprüfungen → Dateiprüfung erstellen*, Pfad `C:\Shares`, *Vorhandene Vorlage verwenden*, Vorlage `Audio- und Videodateien blockieren`, aktive Prüfung. PowerShell:

```powershell
$vorlage = 'Block Audio and Video Files'   # Name aus Schritt 1 einsetzen
New-FsrmFileScreen -Path 'C:\Shares' -Template $vorlage -Active
Get-FsrmFileScreen -Path 'C:\Shares'
```

**3. Wirkung am Client prüfen (auf CL1 als `Sales_User`)**

```powershell
Set-Content -Path '\\FS1\Unternehmensdaten\Vertrieb\test.mp3' -Value 'kein echtes Audio'
Set-Content -Path '\\FS1\Unternehmensdaten\Vertrieb\test.txt' -Value 'Text'
```

Erwartet (*sinngemäß*): Die `.mp3` wird abgelehnt (Fehlermeldung „Zugriff verweigert“ oder ähnlich, *Wortlaut nicht bestätigt*), die `.txt` wird angelegt. Notiere den Wortlaut der Meldung. Lege `test.mp3` auch einmal per Explorer an: Rechtsklick → Neu → Textdokument, umbenennen in `test.mp3` (die Dateinamenerweiterung muss sichtbar sein).

## Hinweise

- Ein **Dateiprüfungsfilter erkennt nur den Dateinamen** (die Endung), nicht den Inhalt. Wer `film.mp4` in `film.dat` umbenennt, umgeht ihn. Er ist deshalb keine Anti-Malware-Lösung.
- Der Filter greift nur beim **Speichern**. Schon vorhandene `.mp3`-Dateien bleiben, das gibt auch die Cmdlet-Dokumentation an.
- Der Filter auf `C:\Shares` gilt auch für die Ordner, die später repliziert werden. In Modul 07 legst du deshalb keine Audio- oder Videodateien in `Vertrieb` an.
- Ein Kontingent zählt die **Daten im Ordner**. Schattenkopien liegen im Schattenkopiespeicher und zählen nicht mit. Ob DFS-R-Staging-Daten in ein Kontingent fallen, ist *nicht bestätigt* (der Lehrplan nennt die Wechselwirkung selbst unbestätigt; in Modul 07 wird sie deshalb vermieden).
- Ein automatisch angewendetes Kontingent (Option *Kontingent automatisch auf neue Unterordner anwenden*, Menüname *nicht bestätigt*) gilt auch für später angelegte Home-Ordner unter `C:\Shares\Home`.

## Kontrollfragen

1. Was ist der Unterschied zwischen einem harten (Hard) und einem weichen (Soft) Kontingent?
2. Warum ist die Dateiprüfung (File Screening) keine zuverlässige Anti-Malware-Lösung?
3. Wie reagiert Windows auf dem Client, wenn ein Dateiprüfungsfilter zuschlägt?

## Musterlösung

<details>
<summary>Antworten und Zielzustand (erst nach dem Versuch öffnen)</summary>

**Zielzustand**

- FSRM ist auf `FS1` installiert.
- `Vertrieb` hat ein hartes Kontingent von 500 MB. `C:\Shares\Home` hat ein Auto-Apply-Kontingent (weich, 85 %), und `IT_Admin` und `Sales_User` haben jeweils ein eigenes Kontingent.
- Auf `C:\Shares` liegt ein aktiver Filter mit der Vorlage für Audio- und Videodateien. `test.mp3` wird abgelehnt.

**Antworten**

1. Ein **hartes** Kontingent verhindert das Speichern über der Grenze. Ein **weiches** Kontingent überwacht nur und löst bei Schwellenwerten Aktionen aus (E-Mail, Ereignis, Befehl), blockiert aber nicht.
2. Der Filter prüft nur Dateinamen und -endungen, nicht den Inhalt. Schadsoftware lässt sich umbenennen oder in erlaubten Formaten verstecken. Er kann außerdem nichts löschen, was schon da ist.
3. Das Speichern schlägt mit einer Fehlermeldung fehl. Meist sieht der Anwender „Zugriff verweigert“ oder eine Meldung, dass der Ordner die Datei nicht annimmt (*Wortlaut nicht bestätigt*). Der Administrator kann zusätzlich eine E-Mail oder einen Ereigniseintrag auslösen lassen.

</details>

## Erweiterungen

- Lege einen **passiven** Filter für `.exe`-Dateien an (ohne `-Active`) und beobachte, was im Ereignisprotokoll steht, obwohl die Datei gespeichert wird.
- Erstelle aus dem Home-Kontingent eine Kontingentvorlage (`New-FsrmQuotaTemplate`), und wende sie auf einen zweiten Ordner an.
- Setze einen Schwellenwert, der eine E-Mail senden würde, und beschreibe, was für den Versand fehlt (SMTP-Server in FSRM-Optionen).
