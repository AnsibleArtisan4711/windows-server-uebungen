# 10.1 Gruppenrichtlinien für RDS: Verbindungsgrenzen, Sitzungslimits und Wirkung prüfen

| | |
|---|---|
| **Modul** | 10 Gruppenrichtlinien für RDS |
| **Stufe** | Fortgeschritten (Priorität 1) |
| **Geschätzte Zeit** | 5 bis 6 Stunden (Schätzung; Lehrplan: 8 UE zu 45 Minuten = 6 Stunden) |
| **Werkzeuge** | Gruppenrichtlinienverwaltung, Windows PowerShell, `gpresult`, `mstsc` |
| **Vorwissen** | Modul 04, Gruppenrichtlinien-Grundlagen |

> [!WARNING]
> **Stand der Prüfung: Entwurf, nicht im Labor ausgeführt.** Der Pfad *Computer Configuration → Administrative Templates → Windows Components → Remote Desktop Services → Remote Desktop Session Host* ist durch Microsoft Learn für die Bereiche *Licensing* und *Security* belegt. **Nicht bestätigt:** die genauen Richtliniennamen und Unterpfade für *Limit number of connections*, die Sitzungslimits (*Session Time Limits*) und den Loopback-Modus. Prüfe sie im Richtlinieneditor. `New-GPO` und `New-GPLink` sind nicht einzeln gegen Microsoft Learn gelesen.

## Lernziele

Nach dieser Übung kannst du

- erklären, welche Einstellungen für Session Hosts über die Computerkonfiguration wirken und wofür der Loopback-Modus gebraucht wird
- eine GPO für die OU `RDS-Server` anlegen und Verbindungsgrenzen sowie Sitzungslimits setzen
- die Wirkung mit `gpresult` nachweisen

## Voraussetzungen

- Modul 04 abgeschlossen.
- Prüfpunkt `vor-M10` auf allen drei VMs vor Beginn.

## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| Computerkonfiguration | Einstellungen, die für den Rechner gelten, unabhängig vom angemeldeten Benutzer. |
| Loopback-Modus | Benutzerrichtlinien werden anhand des Computers statt des Benutzers angewendet; typisch für Session Hosts. |
| Sitzungslimit | Zeitgrenze für getrennte, leerlaufende oder aktive Sitzungen. |

## Testumgebung

| Gerät | Rolle in Modul 10 |
|---|---|
| DC01 | Gruppenrichtlinien |
| RDS01 | Zielserver |
| CL01 | Test |

## Aufgabe

### Teil 1: Prüfpunkt und GPO

*(Lerneinheit 10.1, Praxisaufgabe 1)*

```powershell
foreach ($vm in 'DC01','RDS01','CL01') { Checkpoint-VM -Name $vm -SnapshotName 'vor-M10' }
```

Auf `DC01`:

```powershell
New-GPO -Name 'RDS-Server'
New-GPLink -Name 'RDS-Server' -Target 'OU=RDS-Server,DC=rdslab,DC=internal'
```

### Teil 2: Verbindungsgrenze

*(Lerneinheit 10.2, Praxisaufgabe 2)*

Bearbeite die GPO im Gruppenrichtlinienverwaltungs-Editor. Unter *Computer Configuration → Administrative Templates → Windows Components → Remote Desktop Services → Remote Desktop Session Host → Connections* suchst du die Richtlinie *Limit number of connections* (Name und Pfad *nicht bestätigt*). Aktiviere sie mit dem Wert 2.

### Teil 3: Sitzungslimit

*(Praxisaufgabe 3)*

Unter *…Remote Desktop Session Host → Session Time Limits* setzt du das Limit für getrennte Sitzungen auf 5 Minuten (Richtlinienname *nicht bestätigt*; im Editor nachsehen).

### Teil 4: Wirkung prüfen

*(Lerneinheit 10.3, Praxisaufgabe 4)*

Auf `RDS01`:

```powershell
gpupdate /force
gpresult /h C:\Temp\bericht.html
```

Öffne den Bericht und finde beide Richtlinien. Verbinde `user1` zweimal (zweites Fenster) und notiere das Verhalten. Trenne eine Sitzung, warte die Zeit ab und prüfe, ob sie beendet wird.

### Teil 5: Rückbau

*(Praxisaufgabe 5)*

Setze beide Richtlinien auf *Not configured* oder lösche die GPO (`Remove-GPO -Name 'RDS-Server'`). Prüfe mit `gpresult`, dass die Einstellungen nicht mehr gelten.

## Hinweise

- Lege das Verzeichnis `C:\Temp` an, wenn es fehlt (`New-Item -ItemType Directory -Force`).
- Teste Richtlinien nicht auf dem Domänencontroller.

## Kontrollfragen

1. Warum wirken die Einstellungen aus diesem Modul über die Computerkonfiguration auf alle Benutzer der OU?
2. Wann benötigt man den Loopback-Modus, und welche zwei Varianten gibt es (nicht bestätigt)?
3. Wie stellst du fest, welche GPO eine bestimmte Einstellung setzt?

## Musterlösung

<details>
<summary>Antworten und Zielzustand (erst nach dem Versuch öffnen)</summary>

**Zielzustand**

- GPO `RDS-Server` an der OU `RDS-Server` verknüpft, beide Richtlinien wirksam und im Bericht sichtbar, Verhalten notiert, danach zurückgebaut.

**Antworten**

1. Die GPO hängt an der OU, in der das Computerkonto liegt; Computerkonfiguration gilt für den Rechner und damit für jede Sitzung darauf.
2. Wenn Benutzereinstellungen für alle Anmeldungen am Session Host gelten sollen, unabhängig von der OU des Benutzers. Die zwei Varianten heißen sinngemäß „Replace“ und „Merge“ (nicht bestätigt).
3. Mit `gpresult /h` (Bericht) und der Ansicht „Winning GPO“ im Bericht; der Bericht zeigt je Einstellung die setzende GPO.


</details>
