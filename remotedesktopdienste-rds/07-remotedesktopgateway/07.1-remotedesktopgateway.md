## Lernziele

Nach dieser Übung kannst du

- erklären, wozu RD Gateway dient und welche Aufgaben CAP und RAP haben

- eine Verbindung über das Gateway herstellen und den Ausgangszustand wiederherstellen

## Voraussetzungen

- Modul 06 abgeschlossen (Prüfpunkt `M6-Zert`).

## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| CAP | Connection Authorization Policy: legt fest, wer sich mit dem Gateway verbinden darf. |
| RAP | Resource Authorization Policy: legt fest, auf welche Ressourcen die Verbindung gehen darf. |
| Bypass für lokale Adressen | Option, die lokale Clients das Gateway umgehen lässt. |

## Aufgabe

### Teil 1: Installation

*(Lerneinheit 7.1 und 7.2, Praxisaufgabe 1)*

*Server Manager → Remote Desktop Services → Overview → + RD Gateway*, Server `RDS01`, externer Name `rds.rdslab.internal`. Wähle das Zertifikat aus Modul 06 (*Create new certificate* oder bestehendes `.pfx`). Alternativ in *RD Gateway Manager → Properties → SSL Certificate → Import a certificate into the RD Gateway* (laut Microsoft Learn). PowerShell (Parameter sinngemäß):

```powershell
Add-RDServer -Server 'rds01.rdslab.internal' -Role 'RDS-GATEWAY' -ConnectionBroker 'rds01.rdslab.internal' -GatewayExternalFqdn 'rds.rdslab.internal'
```

### Teil 2: Richtlinien

*(Praxisaufgabe 2)*

Lege im RD Gateway Manager eine **CAP** und eine **RAP** für `SG-RDS-Users` an. Aktiviere in der RAP **nicht** die Einschränkung auf Computer mit Unterstützung für „RD Gateway messaging“ (laut Microsoft Learn unterstützt der hier genutzte Client sie nicht). Gewähre Zugriff auf den Computer `RDS01`.

### Teil 3: Test

*(Lerneinheit 7.3, Praxisaufgabe 3)*

Entferne in *Edit Deployment Properties → RD Gateway* die Option **Bypass RD Gateway server for local addresses**; alternativ:

```powershell
Set-RDDeploymentGatewayConfiguration -BypassLocal $false -ConnectionBroker 'rds01.rdslab.internal' -Force
```

Das Cmdlet hat laut Referenz weitere Pflichtangaben (`-GatewayMode`); lies mit `Get-Help Set-RDDeploymentGatewayConfiguration -Full` nach. In `mstsc`: *Erweitert → Einstellungen* (*nicht bestätigt*), Gateway `rds.rdslab.internal` eintragen, als `RDSLAB\user1` verbinden. Notiere, was anders ist als bei der direkten Verbindung.

### Teil 4: Rückbau

*(Praxisaufgabe 4)*

Stelle *Bypass RD Gateway server for local addresses* wieder auf den Ausgangszustand (aktiviert) und lösche die Gatewayeinstellung in `mstsc`. Ein Zugriff aus dem Internet ist im Labor nicht möglich und wird nicht getestet.

## Hinweise

- Das Gateway ist für den Zugriff von außen gedacht. Öffne keinen Port im Heimnetz für das Labor.
- Dieses Modul ist Priorität 2. Kein späteres Modul setzt es voraus.

2. Was legt die CAP fest und was die RAP?

## Musterlösung

<details>
<summary>Antworten und Zielzustand (erst nach dem Versuch öffnen)</summary>

**Zielzustand**

- Gateway installiert, CAP und RAP für `SG-RDS-Users`, Test über das Gateway durchgeführt, Bypass wieder aktiviert, Gatewayeinstellung in `mstsc` gelöscht.

**Antworten**

1. RD Gateway tunnelt RDP über HTTPS und lässt den Zugriff ohne VPN zu; ein VPN öffnet dagegen das ganze Netz oder Teilnetz.
2. Die CAP bestimmt, wer sich über das Gateway verbinden darf (Benutzergruppe, Authentifizierung); die RAP bestimmt, auf welche internen Ressourcen er zugreifen darf.
3. Der Client baut eine TLS-Verbindung zum Gateway auf und vergleicht den Namen mit dem Zertifikat. Fehlt der Name, warnt der Client oder verbindet nicht.


</details>
