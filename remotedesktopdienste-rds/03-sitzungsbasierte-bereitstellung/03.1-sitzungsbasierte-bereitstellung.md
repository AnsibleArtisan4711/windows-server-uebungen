## Lernziele

Nach dieser Übung kannst du

- eine sitzungsbasierte Standardbereitstellung mit Broker, Web Access und Session Host auf einem Server installieren
- die Rollenverteilung in Server Manager und per PowerShell prüfen
- die Zertifikatswarnung nach der Erstinstallation erklären

## Voraussetzungen

- Modul 02 abgeschlossen (Prüfpunkt `M2-Basis`).
- Alle drei VMs laufen. Keine ausstehenden Neustarts auf `RDS01`.

## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| Standardbereitstellung | Assistent, der die Rollen auf bis zu drei Server verteilt. |
| Sitzungsbasierte Desktopbereitstellung | Variante für Sitzungen auf Session Hosts, im Gegensatz zu virtuellen Desktops. |
| RDMS | Remote Desktop Management Service auf dem Broker, wird für die Verwaltung der Bereitstellung gebraucht. |

## Testumgebung

| Gerät | Rolle in Modul 03 |
|---|---|
| DC01 | Domänencontroller, nicht Teil der Bereitstellung |
| RDS01 | alle drei Rollen |
| CL01 | prüft den Zugriff |

## Aufgabe

### Teil 1: Vorbereitung

*(Lerneinheit 3.1, Praxisaufgabe 1)*

Melde dich auf `RDS01` als Domänenadministrator an. Öffne Server Manager und füge `RDS01` über *Manage → Add Servers → Find Now* hinzu. Notiere, welche Rolle auf welchem Server liegt: alle drei auf `RDS01`. Das ist eine Laborvereinfachung.

### Teil 2: Installation

*(Lerneinheit 3.2, Praxisaufgabe 2)*

Menüweg (laut Microsoft Learn): *Manage → Add Roles and Features → Remote Desktop Services installation → Standard Deployment → Session-based desktop deployment*, `RDS01` für Connection Broker, Web Access und Session Host wählen, *Restart the destination server automatically if required* ankreuzen, *Deploy*.

Alternativ per PowerShell (Syntax aus der Cmdlet-Referenz):

```powershell
New-RDSessionDeployment -ConnectionBroker 'rds01.rdslab.internal' -WebAccessServer 'rds01.rdslab.internal' -SessionHost 'rds01.rdslab.internal'
```

Der Server startet neu. Warte, bis der Server Manager die Bereitstellung als abgeschlossen zeigt.

### Teil 3: Prüfung

*(Lerneinheit 3.3, Praxisaufgabe 3)*

```powershell
Get-RDServer -ConnectionBroker 'rds01.rdslab.internal'
```

Erwartet (*sinngemäß*): `RDS01` mit den Rollen `RDS-CONNECTION-BROKER`, `RDS-WEB-ACCESS`, `RDS-RD-SERVER`. In Server Manager: *Remote Desktop Services → Overview*. Rufe von `CL01` im Browser `https://rds.rdslab.internal/RDWeb` auf und notiere die Zertifikatswarnung.

### Teil 4: Prüfpunkt

*(Praxisaufgabe 4)*

```powershell
foreach ($vm in 'DC01','RDS01','CL01') { Checkpoint-VM -Name $vm -SnapshotName 'M3-RDS' }
```

## Hinweise

- Die Zertifikatswarnung ist in diesem Modul normal. Sie wird in Modul 06 beseitigt.
- Installiere die Bereitstellung nicht auf dem Domänencontroller.

## Kontrollfragen

1. Welche drei Rollendienste installiert die sitzungsbasierte Standardbereitstellung, und welchen Server geben die Parameter von `New-RDSessionDeployment` jeweils an?
2. Warum erscheint nach der Installation eine Zertifikatswarnung im Browser?
3. Warum gehört diese Bereitstellung nicht auf den Domänencontroller?

## Musterlösung

<details>
<summary>Antworten und Zielzustand (erst nach dem Versuch öffnen)</summary>

**Zielzustand**

- Bereitstellung installiert, `Get-RDServer` zeigt drei Rollen auf `RDS01`, Web Access über `https://rds.rdslab.internal/RDWeb` erreichbar (mit Warnung), Prüfpunkt `M3-RDS` auf allen drei VMs.

**Antworten**

1. Connection Broker (`-ConnectionBroker`), Web Access (`-WebAccessServer`) und Session Host (`-SessionHost`); im Labor alle auf `RDS01`.
2. Der Assistent erzeugt selbst signierte Zertifikate. Der Browser auf `CL01` vertraut ihrem Aussteller nicht, und der Name im Zertifikat passt eventuell nicht zu `rds.rdslab.internal`.
3. Ein Domänencontroller sollte keine Benutzersitzungen hosten. Benutzer erhielten sonst interaktive Anmelderechte auf dem Rechner mit dem sensibelsten Verzeichnisdienst.


</details>
