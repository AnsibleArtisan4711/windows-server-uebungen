# 12.1 Sicherheit und Netzwerkebenenauthentifizierung (NLA): prüfen, Richtlinie setzen, Zugriffsfehler beheben

| | |
|---|---|
| **Modul** | 12 Sicherheit und Netzwerkebenenauthentifizierung |
| **Stufe** | Fortgeschritten (Priorität 1) |
| **Geschätzte Zeit** | 5 bis 6 Stunden (Schätzung; Lehrplan: 8 UE zu 45 Minuten = 6 Stunden) |
| **Werkzeuge** | Windows PowerShell, Gruppenrichtlinienverwaltung, Ereignisanzeige, `mstsc` |
| **Vorwissen** | Modul 04, Modul 10 |

> [!WARNING]
> **Stand der Prüfung: Entwurf, nicht im Labor ausgeführt.** Registrywert `UserAuthentication` unter `HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server\WinStations\RDP-Tcp`, die Ursachen des Fehlers „The system administrator has restricted the types of logon“, Ereignis 4625 und `Add-LocalGroupMember` stammen aus Microsoft Learn (12.11.2026). **Nicht bestätigt:** der genaue Pfad der NLA-Richtlinie (laut Lehrplan *…Remote Desktop Session Host → Security → Require user authentication for remote connections by using Network Level Authentication*), die Wirkung der Richtlinie auf einen bereits laufenden Server und der Wortlaut deutscher Fehlermeldungen.

## Lernziele

Nach dieser Übung kannst du

- erklären, was NLA ist und welche Gefahr sie mindert
- NLA und die Zugriffsberechtigung prüfen und konfigurieren
- Schutzmaßnahmen für RDP benennen

## Voraussetzungen

- Modul 04 und Modul 10 abgeschlossen.
- Prüfpunkt `vor-M12` auf allen drei VMs vor Beginn.

## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| NLA | Network Level Authentication: Der Benutzer authentifiziert sich, bevor die Sitzung aufgebaut wird. |
| Remote Desktop Users | Lokale Gruppe, deren Mitglieder sich per Remotedesktop anmelden dürfen. |
| Ereignis 4625 | Sicherheitsereignis „Anmeldung fehlgeschlagen“. |

## Testumgebung

| Gerät | Rolle in Modul 12 |
|---|---|
| RDS01 | Zielserver |
| CL01 | Test |
| DC01 | Gruppenrichtlinie |

## Aufgabe

### Teil 1: Ausgangslage

*(Lerneinheit 12.1, Praxisaufgabe 1)*

```powershell
foreach ($vm in 'DC01','RDS01','CL01') { Checkpoint-VM -Name $vm -SnapshotName 'vor-M12' }
```

Auf `RDS01` den NLA-Zustand lesen (laut Microsoft Learn bedeutet der Wert 0: aus):

```powershell
Get-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Control\Terminal Server\WinStations\RDP-Tcp' -Name 'UserAuthentication'
```

Suche die GPO-Einstellung *Require user authentication for remote connections by using Network Level Authentication* im Editor (Pfad *nicht bestätigt*).

### Teil 2: Richtlinie setzen

*(Lerneinheit 12.2, Praxisaufgabe 2)*

Aktiviere die Richtlinie in der GPO `RDS-Server`, `gpupdate /force` auf `RDS01`, `gpresult /h` prüfen.

### Teil 3: Zugriffsfehler

*(Praxisaufgabe 3)*

Stelle sicher, dass `user2` weder in `SG-RDS-Users` noch in der lokalen Gruppe `Remote Desktop Users` auf `RDS01` ist. Verbinde dich von `CL01` direkt mit `mstsc /v:rds01.rdslab.internal` als `RDSLAB\user2` und notiere die Meldung (laut Quelle „The system administrator has restricted the types of logon (network or interactive) that you may use“) und das Ereignis 4625:

```powershell
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4625} -MaxEvents 5 | Select-Object TimeCreated, Message
```

Behebe den Fehler über die Gruppenmitgliedschaft, **nicht** durch Abschalten von NLA:

```powershell
Add-LocalGroupMember -Group 'Remote Desktop Users' -Member 'RDSLAB\user2'
```

Prüfe und entferne ihn danach wieder aus der Gruppe (`Remove-LocalGroupMember`).

### Teil 4: Härtungs-Checkliste

*(Lerneinheit 12.3, Praxisaufgabe 4)*

Schreibe auf, was du für einen produktiven RDS-Server zusätzlich tun würdest: Updates einspielen (Modul 13), Gateway statt Portfreigabe, Kontosperre und Kennwortrichtlinie in der Domäne (im Labor nicht ändern), Zugriff nur für benannte Gruppen.

### Teil 5: Rückbau

*(Praxisaufgabe 5)*

Entferne die Richtlinie aus der GPO oder setze sie auf *Not configured*. Stelle sicher, dass NLA **nicht** abgeschaltet bleibt.

## Hinweise

- Schalte NLA nie dauerhaft ab, um einen Zugriffsfehler zu umgehen. Der Microsoft-Artikel nennt das Abschalten nur als zeitweilige Prüfung.
- Gib im Labor keinen RDP-Port nach außen frei.

## Kontrollfragen

1. Warum erfolgt die Anmeldung bei NLA vor dem Aufbau der Sitzung, und welchen Angriff erschwert das?
2. Welche beiden Gründe führen zu „The system administrator has restricted the types of logon“?
3. Warum ist das Abschalten von NLA keine gute Lösung?
4. Welche Rolle spielt das Ereignis 4625?

## Musterlösung

<details>
<summary>Antworten und Zielzustand (erst nach dem Versuch öffnen)</summary>

**Zielzustand**

- NLA-Zustand und Richtlinie dokumentiert, Zugriffsfehler reproduziert und über die Gruppe behoben, danach zurückgebaut, NLA aktiv, Checkliste geschrieben.

**Antworten**

1. Der Server verlangt Zugangsdaten, bevor er Ressourcen für die Sitzung bereitstellt. Das erschwert Angriffe, die den Anmeldebildschirm ohne Zugangsdaten belasten (sinngemäß, nicht im Labor getestet).
2. Fehlendes Recht *Allow log on through Remote Desktop Services* beziehungsweise fehlende Gruppenmitgliedschaft (zum Beispiel `Remote Desktop Users`), oder eine GPO, die die Anmeldung verweigert (Deny-Richtlinie).
3. Er löst das Problem nicht, sondern verlagert es: Die Rechteprüfung bleibt falsch, und der Server nimmt Verbindungen ohne Vorab-Authentifizierung an.
4. Es protokolliert fehlgeschlagene Anmeldungen und hilft, den Grund (Logontyp, Benutzer, Quelle) einzugrenzen.


</details>
