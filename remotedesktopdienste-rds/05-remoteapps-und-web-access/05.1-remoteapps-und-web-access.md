> [!WARNING]
> **Stand der Prüfung: Entwurf, nicht im Labor ausgeführt.** `New-RDRemoteApp` und `Get-RDRemoteApp` sind **nicht einzeln gegen Microsoft Learn gelesen**. Der Menüweg zum Veröffentlichen (*Collections → Desktop → RemoteApp Programs → Publish RemoteApp Programs*) und die Pfade der Programme sind *nicht bestätigt*. Die Zertifikatswarnung bestätigst du **nur in diesem Modul**.

## Lernziele

Nach dieser Übung kannst du

- Anwendungen als RemoteApp veröffentlichen
- RemoteApps über RD Web Access starten
- erklären, was RemoteApp von einem Desktop unterscheidet

## Voraussetzungen

- Modul 04 abgeschlossen (Sammlung `Desktop`).
- `user1` ist in `SG-RDS-Users`.

## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| RemoteApp | Anwendung, die auf dem Server läuft und auf dem Client wie ein lokales Fenster erscheint. |
| RD Web Access | Webseite mit der Liste der veröffentlichten Ressourcen. |
| .rdp-Datei | Textdatei mit Verbindungseinstellungen, vom Web Access erzeugt. |

## Testumgebung

| Gerät | Rolle in Modul 05 |
|---|---|
| RDS01 | Session Host und Web Access |
| CL01 | Browser, startet die RemoteApp |

## Aufgabe

### Teil 1: Veröffentlichen

*(Lerneinheit 5.1 und 5.2, Praxisaufgabe 1)*

Veröffentliche Editor und Paint in der Sammlung `Desktop`. Pfade auf dem Server prüfen:

```powershell
Test-Path 'C:\Windows\System32\notepad.exe'
Test-Path 'C:\Windows\System32\mspaint.exe'
```

Befehl (Parameter sinngemäß):

```powershell
New-RDRemoteApp -CollectionName 'Desktop' -DisplayName 'Editor' -FilePath 'C:\Windows\System32\notepad.exe' -ConnectionBroker 'rds01.rdslab.internal'
New-RDRemoteApp -CollectionName 'Desktop' -DisplayName 'Paint'  -FilePath 'C:\Windows\System32\mspaint.exe' -ConnectionBroker 'rds01.rdslab.internal'
Get-RDRemoteApp -CollectionName 'Desktop' -ConnectionBroker 'rds01.rdslab.internal'
```

Oder in Server Manager: *Collections → Desktop → RemoteApp Programs → Tasks → Publish RemoteApp Programs*.

### Teil 2: Web Access

*(Lerneinheit 5.3, Praxisaufgabe 2)*

Rufe von `CL01` `https://rds.rdslab.internal/RDWeb` auf. Bestätige die Zertifikatswarnung nur hier. Melde dich als `RDSLAB\user1` an, starte Editor und notiere, wie sich das Fenster von einem Desktop unterscheidet.

### Teil 3: RDP-Datei

*(Praxisaufgabe 3)*

Speichere die `.rdp`-Datei des RemoteApps und öffne sie im Texteditor. Finde die Zeile mit der Serveradresse (zum Beispiel `full address:s:`; Schlüsselname *nicht bestätigt*) und notiere den Wert.

## Hinweise

- Starte nur Programme, die auf dem Server vorhanden sind. Pfade zu Programmen auf `CL01` funktionieren nicht.
- Melde die RemoteApp-Sitzung am Ende ab.

## Kontrollfragen

1. Warum läuft ein RemoteApp auf dem Server und nicht auf `CL01`, obwohl das Fenster wie ein lokales aussieht?
2. Welche Rolle hat RD Web Access, und was liefert es dem Browser?
3. Warum kommt für ein RemoteApp trotzdem eine RDS-Lizenz in Betracht (siehe Modul 08)?

## Musterlösung

<details>
<summary>Antworten und Zielzustand (erst nach dem Versuch öffnen)</summary>

**Zielzustand**

- Zwei veröffentlichte RemoteApps, Editor über Web Access gestartet, `.rdp`-Datei mit Serveradresse gelesen, Sitzung abgemeldet.

**Antworten**

1. Der Server führt das Programm aus und überträgt nur Bild, Eingaben und Ton per RDP. Das Fenster wird lokal nachgezeichnet.
2. Web Access zeigt die für den Benutzer freigegebenen Ressourcen und liefert eine `.rdp`-Datei, die der RDP-Client öffnet.
3. Auch für RemoteApps verbindet sich der Client mit einem Session Host; die Lizenzpflicht hängt am Zugriff auf den Server, nicht an der Darstellung (Modul 08).


</details>
