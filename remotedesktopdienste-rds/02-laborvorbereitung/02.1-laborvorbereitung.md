# 02.1 Vorbereitung der Laborumgebung: Netzwerk, Domänenbeitritt, OUs, Benutzer und Gruppen

> [!WARNING]
> **Stand der Prüfung: Entwurf, nicht im Labor ausgeführt.** Die Cmdlets `New-VMSwitch`, `Connect-VMNetworkAdapter`, `New-NetIPAddress`, `Set-DnsClientServerAddress`, `Add-DnsServerResourceRecordCName`, `Add-Computer`, `New-ADOrganizationalUnit`, `New-ADUser`, `New-ADGroup`, `Add-ADGroupMember`, `Move-ADObject` und `Checkpoint-VM` sind **nicht einzeln gegen Microsoft Learn geprüft**. Namen der Netzwerkadapter (`Ethernet`) und Ausgaben sind *sinngemäß*. Weicht dein System ab, gilt deine Beobachtung.

## Lernziele

Nach dieser Übung kannst du

- einen privaten Hyper-V-Switch, statische Adressen und einen DNS-Alias einrichten
- Server und Client in die Domäne aufnehmen und die Computerkonten in OUs ordnen
- Benutzer und Gruppen für RDS anlegen
- Prüfpunkte für alle drei VMs gemeinsam erstellen und warum sie gemeinsam zurückgesetzt werden müssen

## Voraussetzungen

- Modul 01 abgeschlossen.
- Hyper-V ist aktiv. `DC01` (Windows Server 2022 Evaluation, Domäne `rdslab.internal`, AD DS und DNS) ist **vor Kursbeginn** aufgebaut; der Aufbau gehört nicht zu diesem Kurs.
- `RDS01` (Windows Server 2022 Evaluation, Desktopdarstellung) und `CL01` (Windows 11 Enterprise Evaluation, Generation 2 mit virtuellem TPM) sind installiert, noch nicht in der Domäne.
- Evaluationsmedien wurden **vor** diesem Modul außerhalb des Labors geladen. Das Labor hat danach kein Internet.

## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| Privater Switch | Hyper-V-Switch ohne Verbindung zum Host und zu anderen Netzen; nur die VMs sehen sich. |
| CNAME | Alias im DNS; `rds` zeigt auf `rds01`. |
| OU | Organisationseinheit im AD, an die später Gruppenrichtlinien gebunden werden. |
| Prüfpunkt (Checkpoint) | Zustand einer VM, auf den man zurückgehen kann; bei mehreren VMs gemeinsam setzen. |

## Testumgebung

| Gerät | Rolle in Modul 02 |
|---|---|
| DC01 | Domänencontroller, DNS, 192.168.70.10 |
| RDS01 | späterer RDS-Server, 192.168.70.20 |
| CL01 | Windows-11-Client, 192.168.70.50 |

## Aufgabe

### Teil 1: Netzwerk

*(Lerneinheit 2.1, Praxisaufgabe 1)*

Auf dem Hyper-V-Host:

```powershell
New-VMSwitch -Name 'vSwitch-RDS-Privat' -SwitchType Private
foreach ($vm in 'DC01','RDS01','CL01') { Connect-VMNetworkAdapter -VMName $vm -SwitchName 'vSwitch-RDS-Privat' }
```

In den VMs (Adaptername mit `Get-NetAdapter` prüfen; hier `Ethernet`, *nicht bestätigt*):

```powershell
# auf RDS01
New-NetIPAddress -InterfaceAlias 'Ethernet' -IPAddress 192.168.70.20 -PrefixLength 24
Set-DnsClientServerAddress -InterfaceAlias 'Ethernet' -ServerAddresses 192.168.70.10
```

Auf `CL01` ebenso mit `192.168.70.50`, auf `DC01` mit `192.168.70.10` (DNS: sich selbst). Prüfen:

```powershell
Test-NetConnection 192.168.70.10
```

### Teil 2: DNS und Domäne

*(Praxisaufgabe 2)*

Auf `DC01`:

```powershell
Add-DnsServerResourceRecordA -ZoneName 'rdslab.internal' -Name 'rds01' -IPv4Address 192.168.70.20
Add-DnsServerResourceRecordCName -ZoneName 'rdslab.internal' -Name 'rds' -HostNameAlias 'rds01.rdslab.internal'
```

(Wenn `RDS01` sich beim Domänenbeitritt selbst registriert, ist der A-Eintrag bereits da; dann den ersten Befehl auslassen.) Auf `RDS01` und `CL01`:

```powershell
Add-Computer -DomainName 'rdslab.internal' -Credential (Get-Credential) -Restart
```

### Teil 3: OUs, Benutzer und Gruppen

*(Praxisaufgabe 3)*

Auf `DC01`:

```powershell
New-ADOrganizationalUnit -Name 'RDS-Server' -Path 'DC=rdslab,DC=internal'
New-ADOrganizationalUnit -Name 'Clients' -Path 'DC=rdslab,DC=internal'
Move-ADObject -Identity (Get-ADComputer 'RDS01').DistinguishedName -TargetPath 'OU=RDS-Server,DC=rdslab,DC=internal'
Move-ADObject -Identity (Get-ADComputer 'CL01').DistinguishedName -TargetPath 'OU=Clients,DC=rdslab,DC=internal'
New-ADGroup -Name 'SG-RDS-Users' -GroupScope Global -Path 'DC=rdslab,DC=internal'
New-ADGroup -Name 'SG-RDS-Verwaltung' -GroupScope Global -Path 'DC=rdslab,DC=internal'
$pw = Read-Host -AsSecureString 'Kennwort fuer user1'
New-ADUser -Name 'user1' -SamAccountName 'user1' -AccountPassword $pw -Enabled $true
$pw = Read-Host -AsSecureString 'Kennwort fuer user2'
New-ADUser -Name 'user2' -SamAccountName 'user2' -AccountPassword $pw -Enabled $true
Add-ADGroupMember -Identity 'SG-RDS-Users' -Members 'user1'
```

Das Kennwort tippst du interaktiv ein. Es steht nicht im Skript. Lege die Benutzer im Standardcontainer an; eine eigene OU dafür ist nicht nötig. Beachte die Kennwortrichtlinie der Domäne (Länge, Komplexität).

### Teil 4: Basisprüfung und Prüfpunkt

*(Praxisaufgabe 4)*

Von `CL01`:

```powershell
Resolve-DnsName rds.rdslab.internal
Test-NetConnection rds01.rdslab.internal -Port 3389
```

Der zweite Test schlägt fehl oder meldet „False“, weil noch kein RDS installiert ist (Remotedesktop aktivieren ist nicht Teil dieser Übung). Notiere das Ergebnis. Erstelle dann auf dem Host den Prüfpunkt auf **allen drei VMs**:

```powershell
foreach ($vm in 'DC01','RDS01','CL01') { Checkpoint-VM -Name $vm -SnapshotName 'M2-Basis' }
```

## Hinweise

- Das Labor hat keine Verbindung zum Heim- oder Produktivnetz. Vergib keine Adresse aus dem Heimnetz.
- Setze Prüfpunkte der drei VMs nur gemeinsam zurück. Ein einzelner Rücksetzer des Domänencontrollers kann das Verzeichnis gegen die anderen VMs verschieben.
- Kennwörter nie in Skripte oder Berichte schreiben.

## Kontrollfragen

1. Warum erhält das Labor keine Verbindung zum Heimnetz?
2. Wozu dient der CNAME `rds`, und welche Rolle spielt er später bei Zertifikaten?
3. Warum müssen Prüfpunkte der drei VMs gemeinsam zurückgesetzt werden?

## Musterlösung

<details>
<summary>Antworten und Zielzustand (erst nach dem Versuch öffnen)</summary>

**Zielzustand**

- `DC01`, `RDS01` und `CL01` im privaten Netz, `RDS01` in der OU `RDS-Server`, `CL01` in `Clients`, `user1` in `SG-RDS-Users`, `user2` nicht, CNAME `rds` löst auf `192.168.70.20` auf, Prüfpunkt `M2-Basis` auf allen drei VMs.

**Antworten**

1. Die Evaluationsmedien und Fehler im Labor (zum Beispiel ein Dienst, der Daten nach außen sendet) sollen niemanden außerhalb erreichen oder stören. Ein privater Switch isoliert die VMs.
2. Web Access und Gateway sollen unter einem festen Namen erreichbar sein, der nicht vom Servernamen abhängt. Das Zertifikat muss diesen Namen enthalten (Modul 06).
3. (Allgemeines AD-Wissen, in dieser Sitzung nicht nachgelesen.) Ein Domänencontroller führt eine Aktualisierungssequenznummer (USN) im Verzeichnis. Wird nur er zurückgesetzt, passen die Stände zu den Mitgliedsrechnern nicht mehr; Kennwörter der Computerkonten und Replikationsdaten können abweichen.


</details>
